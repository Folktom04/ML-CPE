# UV Guard: คำถามที่คาดว่าจะถูกถามตอนนำเสนอ (4 พ.ย. 2026)

เอกสารเตรียมตอบคำถาม ตัวเลขทุกตัวคัดมาจาก `docs/report.md` และไฟล์ที่ระบุในวงเล็บเหลี่ยม ไม่มีการคำนวณใหม่ · ระบบนี้เป็นค่าประมาณเพื่อการศึกษาและการเตือน ไม่ใช่การวินิจฉัยทางการแพทย์

## 1. ระบบนี้ช่วยอะไร
UV Guard บอกผู้ใช้ว่า "ตอนนี้ ตรงนี้ UV แรงแค่ไหน และผิวของเราจะไหม้ในกี่นาที" แล้วเตือนก่อนจะไหม้ โดยใช้แค่มือถือกับข้อมูลฟรีจากอินเทอร์เน็ต ไม่มีเครื่องวัดหรืออุปกรณ์เสริม
- ประเมิน UVI, UVA, UVB ที่ตำแหน่งผู้ใช้ทุกชั่วโมง พร้อมพยากรณ์ 24 ชม.
- แปลงเป็นเวลาก่อนผิวไหม้ตามประเภทผิว I–VI (แบบสอบถาม 5 ข้อ ดัดแปลงจาก Fitzpatrick)
- แจ้งเตือนในเครื่อง: สรุปตอนเช้า 07:00, UV สูง, UV ลดลงแล้ว, ใกล้ถึงเวลาผิวไหม้ (ปุ่ม "ออกแดด"), ทาครีมซ้ำ

## 2. ต่างจากแอปพยากรณ์อากาศทั่วไปอย่างไร
1. **แม่นกว่าค่าฟรีที่มีอยู่:** MAE 0.479 UVI เทียบ `uv_index` ของ Open-Meteo 1.244 บน test ปี 2025 และ Open-Meteo อิ่มตัวที่ราว UVI 9.3 `[docs/test_2025_criteria.csv]`
2. **บอกช่วงความไม่แน่นอน:** ช่วง q10–q90 ปรับด้วย CQR ครอบคลุมค่าจริง 80.6 % (เป้า 80 %) `[docs/test_2025_criteria.csv]`
3. **เตือนตามค่าบน (q90):** recall ชั่วโมง ≥ สูงมาก 0.986, รุนแรงมาก 19 จาก 23 ชม. (0.826), false alarm 0.163 `[docs/test_2025_criteria.csv]`
4. **เฉพาะตัวผู้ใช้:** เวลาผิวไหม้ตามประเภทผิว และนับปริมาณ UV สะสมจริงตั้งแต่กด "ออกแดด"
5. **แยก UVA กับ UVB:** UVA ทำให้ผิวแก่ก่อนวัยและผ่านกระจกได้ UVB ทำให้ผิวไหม้
6. **วัดผลตรงไปตรงมา:** ประกาศเกณฑ์ 15 ข้อก่อนเปิด test ผ่าน 14 ข้อ รายงานข้อที่ไม่ผ่าน (T4) และไม่ใส่โมเดลที่ทดลองแล้วไม่ชนะ (LSTM, Himawari)

## 3. ไม่มีเครื่องวัด UV แล้วรู้ได้อย่างไรว่าแม่นแค่ไหน
เทียบกับเครื่องวัดบนดาวเทียมและข้อมูลอ้างอิงอิสระ และทดสอบกับข้อมูลที่โมเดลไม่เคยเห็น
| แหล่งอ้างอิง | คืออะไร | ผลปี 2025 (MAE) |
|---|---|---|
| NASA POWER รายชั่วโมง | ค่า UV จากดาวเทียม/แบบจำลอง (เป้าตอนฝึก แต่ปี 2025 กันไว้ทดสอบ) | 0.479 UVI |
| OMI บนดาวเทียม Aura | เครื่องวัดสเปกตรัม UV จริง วัดวันละครั้งตอนเที่ยง | 1.320 (ดีกว่า NASA POWER เอง 1.330 และ baseline ดีสุด 1.960) |
| TEMIS (KNMI) | UVI วันฟ้าใสที่กรุงเทพฯ | 1.360 วันฟ้าเปิด |
- กันข้อมูล test ปี 2025 ตั้งแต่โค้ดอ่านไฟล์ และเปิดครั้งเดียวหลัง refit · ข้อมูลใหม่ ม.ค.–มิ.ย. 2026: MAE 0.470, เทียบ OMI 0.976 `[docs/sat_test_2026_results.json]`
- ข้อจำกัด: NASA POWER เฉลี่ยพื้นที่ราว 1° จึงพิสูจน์ความแม่นยำ ณ จุดที่ยืนไม่ได้ · OMI วัดวันละครั้ง · ประเมินเฉพาะปทุมธานี
- ต่อยอด: ขอข้อมูลสถานีวัด UV ภาคพื้นดิน (ม.ศิลปากร นครปฐม) มาใช้ตรวจผล

## 4. ใช้โมเดลกี่ตัว เทรนกี่ครั้ง แบ่งข้อมูลอย่างไร
**ในแอป 4 ตัว:** (1) XGBoost multi-output ทำนาย CMF ของ UVI/UVA/UVB (2) XGBoost quantile + CQR ให้ช่วง q10–q90 (3) CNN MobileNetV3Small จำแนกสภาพท้องฟ้า 6 แบบ (SWIMCAT-ext) (4) head สัดส่วนเมฆจาก SWIMSEG · ภาพท้องฟ้าเป็นข้อมูลประกอบ ไม่เปลี่ยนค่า UV
**ทดลองแล้วไม่ใช้:** baseline 3 ตัว, LSTM (dev 0.463 ไม่ต่ำกว่า XGBoost 0.450 − 0.02), head CCSN, XGBoost + Himawari (test 2026 ดีขึ้นแค่ 0.007)
**การฝึก:** Optuna 100 trials (complete 42, pruned 58) วัดด้วย CV แล้ว refit ครั้งสุดท้ายบน 2023–2024 · CNN 3 seeds (42/43/44)
**การแบ่งข้อมูลตามเวลา:** Train 2023 · Dev 2024 · CV TimeSeriesSplit 5 folds ใน 2023–2024 เว้น gap 1 วัน · Test 2025 เปิดครั้งเดียว (3,718 ชม.) · SWIMSEG แบ่งตามวันถ่าย (train 9 / val 3 / test 5 วัน) · ตรวจข้อมูลรั่วผ่าน 5/5

## 5. ทำไมใช้ฟิสิกส์ × ML ไม่ใช้ ML ทำนาย UV ตรง ๆ
ฟิสิกส์ (สูตร Madronich สำหรับ UVI, pvlib SPECTRL2 สำหรับ UVA/UVB) ให้ค่าฟ้าใสตามมุมดวงอาทิตย์และโอโซนอยู่แล้ว ML ทำนายแค่ **CMF (Cloud Modification Factor, 0–1)** คือสัดส่วนที่เมฆและฝุ่นลด UV ลง ผลคือ UV = ฟ้าใส × CMF ทำให้ค่ากลางคืนเป็น 0 เสมอ และโมเดลไม่ต้องเรียนรูปร่างของวันเอง · โอโซนใช้ค่าเฉลี่ยรายเดือนจาก NASA POWER 2023–2024 (ไม่ใช้ 300 DU คงที่ ซึ่งทำให้ UVI ต่ำไปราว 15 %)

## 6. ทำไมเตือนตามค่าบน (q90) ไม่ใช้ค่ากลาง
การเตือนผิวไหม้ควรผิดไปทาง "เตือนเร็ว" มากกว่า "เตือนช้า" ค่าบนของช่วงจึงใช้คำนวณเวลาผิวไหม้และตัดสินการเตือน เกณฑ์ ≥ สูงมาก จับได้ 98.6 % โดยเตือนผิด 16.3 % ข้อแลกเปลี่ยนคือ precision ระดับรุนแรงมากยังต่ำ (0.17)
- **ถ้าถูกถามว่า precision ลดลง โมเดลแย่ลงไหม:** ไม่ใช่ตัวโมเดลแย่ลง แต่เป็นการเลือกจุดตัดสินใจ q90 = คิดจากกรณีแดดแรงที่สุดที่เป็นไปได้ไว้ก่อน บน dev ชั่วโมง UV ≥ 8 ที่ไม่เตือนลดจาก 16 เหลือ 1 ใน 100 (recall 0.839 → 0.989) แลกกับ precision 0.765 → 0.596 คือเตือน 10 ครั้ง UV ถึง 8 จริง 6 ครั้ง เตือนเกิน = ผู้ใช้ทาครีมหรือเข้าร่มเร็วขึ้น เตือนพลาด = ผิวไหม้ `[docs/quantile_alerts_cv_folds3-5.csv]`
- **อย่าพูดว่า "การันตี 100 %":** test 2025 จับได้ 98.6 % ระดับรุนแรงมาก 19/23 และการแจ้งเตือนบนมือถือยังช้าได้ (ข้อ 12)

## 6.1 MAE 0.479 แปลว่าผู้ใช้ได้อะไร
ผิวประเภท I มี MED 200 J/m² ส่วนประเภท VI 1,000 J/m² คนผิวขาวมากจึงไหม้เร็วที่สุดและอ่อนไหวต่อความคลาดเคลื่อนที่สุด ตัวอย่างคำนวณที่ UVI 5: ผิว I ไหม้ใน 200 / (5 × 0.025 × 60) ≈ 27 นาที ถ้าประเมินต่ำไปเท่าค่าผิดเฉลี่ยของเรา (0.479) เวลาคลาดราว 3 นาที ของ Open-Meteo (1.244) ราว 9 นาที · ค่าผิดเฉลี่ยวัดเทียบ NASA POWER (ดาวเทียม) ไม่ใช่เครื่องวัดภาคพื้นดิน และแอปใช้ค่าบน q90 จึงเอียงไปทางเตือนเร็ว `[docs/test_2025_results.json]`

## 7. ข้อมูลมาจากไหน
- **Features (ตอนใช้งานจริงก็มี):** Open-Meteo Historical Forecast / Forecast API (สภาพอากาศ) + Air Quality API (AOD, ฝุ่น, PM2.5) + เรขาคณิตดวงอาทิตย์และเวลา รวม 23 features
- **Target (ใช้ตอนฝึกเท่านั้น):** NASA POWER hourly `ALLSKY_SFC_UV_INDEX`, `ALLSKY_SFC_UVA`, `ALLSKY_SFC_UVB` เลือกด้วยกฎที่ประกาศก่อนดูผล (NASA POWER MAE เทียบ OMI 1.143 เทียบ Open-Meteo 2.428 ปี 2023)
- **ห้ามใช้ NASA POWER เป็น feature** เพราะไม่มีตอนใช้งานจริงและเป็น target leakage
- **ภาพท้องฟ้า:** dataset สาธารณะเท่านั้น (CCSN, SWIMCAT-ext, SWIMSEG) ภาพที่ถ่ายในแอปไม่นำไปฝึก

## 8. ความเป็นส่วนตัว
- พิกัด GPS ปัดเหลือราว 1 กม. ก่อนส่งคำนวณ และไม่เก็บพิกัดในเครื่อง
- ส่งข้อมูลขึ้นเซิร์ฟเวอร์เฉพาะเมื่อผู้ใช้ยินยอม (ปิดไว้ตั้งแต่แรก) และส่งแค่ประเภทผิว จังหวัด และการตั้งค่า ไม่ส่งพิกัด
- ภาพท้องฟ้าวิเคราะห์แล้วไม่เก็บ ภาคสนามตรวจแล้ว `has_exif=False` ทุกภาพ (17 ภาพ)
- "ลบข้อมูลของฉัน" ลบทั้งในเครื่องและบนเซิร์ฟเวอร์ (ทดสอบ 25 ต.ค. log `DELETE /users/4 204`)

## 10. ข้อจำกัดหลัก (พูดตรง ๆ)
1. ไม่มีเครื่องวัด UV จริง ค่าอ้างอิงมาจากดาวเทียมและแบบจำลอง
2. ฝึกและประเมินเฉพาะปทุมธานี ที่อื่นยังไม่ได้ประเมิน (แอปขึ้นคำเตือนเมื่อห่างเกิน 50 กม.)
3. CNN ภาพท้องฟ้ายังไม่ได้วัดผลกับภาพจากมือถือ
4. ยังไม่ได้ทดสอบ push จากเซิร์ฟเวอร์จริงและ iOS
5. แจ้งเตือนช้า 21–57 นาทีเมื่อล็อกจอ ไม่นับเป็นแค่ข้อจำกัด แต่เป็นความเสี่ยงวิกฤตและเงื่อนไขบังคับก่อนเผยแพร่ (ข้อ 12)
6. ไม่ใช่เครื่องมือแพทย์ แบบสอบถามผิวยังไม่ผ่านการตรวจสอบทางวิชาการ และค่า MED ยังไม่มีแหล่งอ้างอิง

## 11. ถ้าทำต่อจะทำอะไร
**ต้องทำก่อนเผยแพร่ (ไม่ใช่งานต่อยอด):** แจ้งเตือนตรงเวลาด้วย `SCHEDULE_EXACT_ALARM` และทดสอบซ้ำบนมือถือจริงขณะล็อกจอ
**งานต่อยอด:** ข้อมูลวัด UV ภาคพื้นดิน · ทดสอบหลายพื้นที่ · เก็บภาพท้องฟ้าจากมือถือพร้อมค่า UV อ้างอิงเพื่อวัดว่า CNN ช่วยได้จริงไหม · ปรับเทียบ lux · push จริงผ่าน FCM และ iOS · ปรับการเตือนระดับรุนแรงมาก · ทดลองดาวเทียม Himawari ใหม่กับช่วงฤดูฝน

## 12. แจ้งเตือนช้าแบบนี้ ระบบยังใช้ได้ไหม
พูดตรง ๆ ว่าเป็นความเสี่ยงวิกฤต รอบ 3 พ.ย. ผิว I กดออกแดด 14:34 ควรเตือน (80 %) ราว 14:55 ถึง MED เต็มราว 15:00 แต่แจ้งเตือนมาถึง 15:16 คือหลังผิวเริ่มไหม้ ทั้ง 3 รอบช้า 21–57 นาทีเมื่อล็อกจอ สาเหตุคือแอปตั้งแจ้งเตือนแบบไม่ระบุเวลาแน่นอน (inexact) Android จึงเลื่อนเพื่อประหยัดแบต ระยะเผื่อ 80 % ได้ราว 5 นาที (ผิว I ที่ UVI 5) ไม่พอ · ระยะเผื่อ 80 % ออกแบบไว้ตั้งแต่วัน 22 เพื่อเผื่อเวลาเข้าร่ม ไม่ได้ออกแบบมาเพื่อรองรับความล่าช้านี้ · แนวทาง: `SCHEDULE_EXACT_ALARM` เป็นเงื่อนไขบังคับก่อนเผยแพร่ ระหว่างนี้การ์ด % ของ MED ในแอปอัปเดตตรงเวลาเมื่อเปิดดู `[docs/field_test_2026-11-03.md]`, `[dataset/field/field_notifications_2026-10.csv]`

## 13. CNN แม่น 97.5 % แล้วทำไมไม่เอามาใช้ปรับ UV
เป็นระบบที่อยู่ระหว่างทดลอง ตัวเลข 97.5 % และ MAE 0.084 วัดบน dataset สาธารณะ (SWIMCAT-ext, SWIMSEG) ยังไม่มีภาพจากมือถือในปทุมธานีที่จับคู่กับค่า UV อ้างอิงได้ จึงวัดไม่ได้ว่าช่วยลดความคลาดเคลื่อนของ UV หรือไม่ และภาพมือถือภาคสนามต่างจากภาพฝึก (ออก "เมฆบางสีขาว" ซ้ำ ๆ) จึงแสดงเป็นข้อมูลประกอบ ขั้นต่อไปคือเก็บภาพพร้อมค่าอ้างอิง วัดผล แล้วจึงรวมเข้าการคำนวณหลัก `[docs/sky_cnn_test.json]`, `[docs/sky_cloud_test.json]`
