เวลารวมประมาณ 12 นาที 30 วินาที (เกณฑ์ 10–15 นาที) แล้วต่อด้วยถาม-ตอบ 5–10 นาที
ตัวเลขทุกตัวในสคริปต์มาจากสไลด์ (มีไฟล์ที่มาที่ท้ายสไลด์แต่ละหน้า) และ `docs/field_test_2026-11-03.md` คำตอบที่เตรียมไว้อยู่ใน `docs/presentation_qa.md`

**หลักการพูด:** ตัวเลขทุกตัวต้องตามด้วยประโยคว่า "แปลว่าผู้ใช้ได้อะไร" ห้ามปล่อยตัวเลขลอย ๆ

**สัญลักษณ์:** [ทำ] = สิ่งที่ต้องทำ · **ตัวหนา** = คำที่ควรเน้น · / = เว้นจังหวะสั้น

## ก่อนขึ้นพูด (10 นาทีก่อนถึงคิว)
1. ต่อโน้ตบุ๊กกับมือถือเข้าเครือข่ายเดียวกัน แล้วดู IP ของโน้ตบุ๊กด้วย `ipconfig`
2. เปิด PowerShell หน้าต่างที่ 1 (API):
   `$env:PYTHONPATH = "source_code"; .venv\Scripts\python.exe -m uvicorn api.main:app --app-dir source_code --host 0.0.0.0 --port 8000`
3. เปิด PowerShell หน้าต่างที่ 2 (Expo) โดยใส่ IP ที่ได้จากข้อ 1:
   `$env:EXPO_PUBLIC_API_URL = 'http://<IP>:8000'; npx expo start --dev-client --clear`
4. เปิดแอป **UV Guard (development build)** ไม่ใช่ Expo Go แล้วดูว่าหน้าหลักขึ้นค่า UV
5. ในมือถือ เปิด `http://<IP>:8000/health` ให้ขึ้น ok
6. ในเบราว์เซอร์โน้ตบุ๊ก เปิดแท็บ `http://localhost:8000/docs` รอไว้
7. เปิดวิดีโอแจ้งเตือนผิวไหม้ค้างไว้ที่เฟรมแรก
8. ตั้งผิวในแอปเป็นประเภท III ไว้ก่อน เพื่อให้เปลี่ยนเป็น I และ VI ตอนสาธิตได้

## หน้า 1 · ปก (0:00–0:30)

UV Guard เป็นแอปมือถือที่ตอบ 3 อย่าง: ตอนนี้ UV เท่าไร / อีกกี่นาทีผิวของเราจะไหม้ / และเตือนก่อนถึงเวลานั้น

## หน้า 2 · ปัญหา (0:30–1:30)
ลองนึกว่าเราเปิดแอปพยากรณ์อากาศดู UV ก่อนออกจากบ้านครับ / ค่าฟรีอย่าง Open-Meteo มีปัญหา 3 ข้อ

ข้อแรก ผิดเฉลี่ย **2.4 หน่วย** เมื่อเทียบดาวเทียม OMI / ระดับ WHO แต่ละขั้นกว้างแค่ 2 ถึง 3 หน่วย / **แปลว่าวันที่ควรขึ้น "สูง" อาจขึ้น "ปานกลาง"** แล้วเราก็ไม่ทาครีม
ข้อสอง ค่า **ตันที่ราว 9.3** / วันที่ UV 11 ขึ้นไปซึ่งอันตรายที่สุด **ผู้ใช้จะไม่เคยเห็นคำว่า "รุนแรงมาก" เลย**
ข้อสาม ไม่บอกว่า **ผิวของเราอยู่กลางแดดได้กี่นาที**

UV Guard จึงตอบ 3 คำถามนี้ / UV ตอนนี้พร้อมช่วง q10 ถึง q90 / เวลาก่อนผิวไหม้ตามประเภทผิว 1 ถึง 6 โดย **คิดจากค่าบนเสมอ** / และควรทำอะไร

[ทำ] ชี้ภาพขวา / ภาพนี้คือหน้าหลักของแอปจริงครับ UVI 7.1 ช่วง 6.0 ถึง 8.1 แถบเตือนคิดจากค่าบน 8.1

## หน้า 3 · ภาพรวมระบบ (1:30–2:15)

ส่วนสีส้มคือหัวใจของงาน / **ฟิสิกส์คูณ ML** และ **ช่วงความไม่แน่นอน**
จากนั้น **Risk Engine** แปลงค่า UV เป็นระดับ WHO เวลาก่อนผิวไหม้ และคำแนะนำ SPF/PA / ส่งผ่าน FastAPI ไปที่แอปบนมือถือ

กรอบเส้นประด้านล่างคือ **ระบบภาพท้องฟ้าที่อยู่ระหว่างทดลอง** จะเล่าหลังสาธิตครับ

## หน้า 4 · ฟิสิกส์ × ML (2:15–3:15)
แนวคิดหลักคือ / ผม **ไม่ให้ ML ทาย UV ตรง ๆ** ครับ

ส่วนที่ฟิสิกส์รู้อยู่แล้ว คือดวงอาทิตย์อยู่สูงแค่ไหนและโอโซนเท่าไร ใช้สูตรคำนวณ / **แปลว่ากลางคืนได้ 0 เสมอ และเช้าเย็นลดตามมุมแดดเอง** ML ไม่ต้องเดา
ส่วนที่ยากคือเมฆกับฝุ่น / ให้ XGBoost ทายตัวคูณ **CMF** ว่าเหลือ UV ไว้กี่ส่วน เช่น 0.5 คือเหลือครึ่งเดียว

คำตอบที่ใช้ฝึกมาจาก NASA POWER / เลือกด้วย **กฎที่ประกาศก่อนดูผล** / และ **ไม่ใช้คอลัมน์ของ NASA เป็น input** เพราะจะเท่ากับให้โมเดลดูเฉลย
[ทำ] ชี้แถบปี / แบ่งตามเวลา ฝึก 2023 / เลือกโมเดลด้วย 2024 / กัน 2025 ไว้ทดสอบ **ครั้งเดียว**

[ทำ] ชี้แถบล่าง / ตัวอย่างจริงเมื่อวาน / แอปบอก 4.4 ช่วง 3.7 ถึง 5.0 / คนผิวประเภท I แอปใช้ค่าบน 4.95 / **คำนวณได้ว่าควรหลบแดดภายใน 26 นาที**

## หน้า 5 · ผลบน dev 2024 (3:15–4:30)
หน้านี้คือ **การตัดสินใจที่สำคัญที่สุดในการออกแบบ** ครับ

ถ้าเตือนด้วยค่ากลาง q50 / ในทุก 100 ชั่วโมงที่แดดแรงมาก **ระบบจะเงียบไป 16 ชั่วโมง**
ผมจึงเตือนด้วยค่าบน **q90** / คือ **คิดจากกรณีที่แดดแรงที่สุดที่เป็นไปได้ไว้ก่อน** เผื่อเหลือดีกว่าเผื่อขาด / เหลือไม่เตือนแค่ราว **1 ใน 100** ชั่วโมง (recall 0.839 → 0.989)

**เราออกแบบให้ระบบยอมเตือนเกินไปบ้าง / เพื่อแลกกับการที่ในชั่วโมงแดดแรงมาก เกือบทุกชั่วโมงระบบจะเตือนให้ผู้ใช้เข้าร่ม**
เหมือนเบรกรถครับ / สิ่งที่คนขับต้องการคือ **หยุดได้ทันก่อนชนคนข้ามถนน** / ไม่ใช่เบรกให้น้อยครั้งที่สุด

ราคาที่จ่ายคือ precision ลดเป็น 0.596 / **แปลว่าเตือน 10 ครั้ง UV ถึง 8 จริง 6 ครั้ง** อีก 4 ครั้งผู้ใช้แค่ทาครีมหรือเข้าร่มเร็วขึ้น / **เตือนเกินเสียเวลาเล็กน้อย / เตือนพลาดคือผิวไหม้**

[ทำ] ชี้กล่องขวาบน / ช่วงที่แอปแสดง ตอนแรกแคบเกินไป ครอบค่าจริงแค่ 6 ใน 10 / ผมใช้ CQR ขยายจนครอบ **8 ใน 10** / **ผู้ใช้จึงเชื่อช่วงที่เห็นได้**
ส่วนความแม่นรวม XGBoost ดีที่สุด ผิดเฉลี่ย 0.462 / ตรวจด้วย cross-validation ตามเวลา 5 folds

สองรอบแรกเจอ **บั๊ก 6 ตัว** ที่เทสอัตโนมัติไม่เจอ แก้แล้วทั้งหมด / รอบ 3 ไม่มีบั๊กใหม่ / pytest 402 และ Jest 340 ผ่าน

ข้อจำกัดอื่น / หนึ่ง **ไม่มีเครื่องวัด UV ภาคพื้นดิน** ค่าอ้างอิงเป็นดาวเทียม และ NASA POWER ต่ำกว่า TEMIS 1.36 ในวันฟ้าเปิด / สอง ฝึกที่ปทุมธานีที่เดียว / สาม ระดับรุนแรงมากมีแค่ 23 ชั่วโมง precision 0.17
ส่วนแจ้งเตือนช้า **ไม่ได้นับเป็นแค่ข้อจำกัด** แต่เป็นเงื่อนไขที่ต้องแก้ก่อนเผยแพร่ตามหน้า 8

## หน้า 11 · สรุป (11:45–12:30)
สรุป 3 ข้อครับ
หนึ่ง / **มือถือกับข้อมูลฟรี** บอกได้ว่าผิวของแต่ละคนอยู่กลางแดดได้กี่นาที โดยไม่มีอุปกรณ์เสริม
สอง / ในชั่วโมงแดดแรงมาก 100 ชั่วโมง **ระบบเตือน 99** / และเวลาผิวไหม้คลาดแค่ **ระดับนาที** / ผลนี้มาจากเกณฑ์ที่ประกาศก่อนและเปิด test ครั้งเดียว
สาม / ก่อนเผยแพร่จริง **ต้องทำให้แจ้งเตือนถึงมือผู้ใช้ตรงเวลา**

เพราะ **นวัตกรรมที่สมบูรณ์ไม่ใช่แค่คำนวณแม่น / แต่ต้องปกป้องผู้ใช้ในโลกจริงได้ทันเวลา**
ผลทั้งหมดเป็นค่าประมาณเพื่อการศึกษาและการเตือน ไม่ใช่การวินิจฉัยทางการแพทย์ครับ
