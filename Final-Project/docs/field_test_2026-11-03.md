## รายละเอียด

### E3. เวลาก่อนผิวไหม้ (ตรวจสูตร)
แอปใช้ค่าบน (q90) และปัดลง: MED / (UVI × 0.025 × 60) ที่ค่าบน ≈ 4.95
- I: 200 / (4.95 × 1.5) = 26.9 → 26 นาที
- III: 350 / (4.95 × 1.5) = 47.1 → 47 นาที
- VI: 1000 / (4.95 × 1.5) = 134.7 → มากกว่า 2 ชม.

### E5. ออกแดดและแจ้งเตือน
| แจ้งเตือน | ผิว | เวลาที่ควรได้ | ได้รับ | ช้า | สภาพเครื่อง |
|---|---|---|---|---|---|
| ใกล้ถึงเวลาผิวไหม้ (ประมาณ) | I | ~14:55 (ตามสูตร) | 15:16 | ~21 นาที | ล็อกจอช่วง 14:34–14:55 · ระหว่างรอผู้ทดสอบตั้งแอปเป็น "ไม่พัก" (ไม่จำกัดแบต) · ห้ามรบกวนปิด |
| ถึงเวลาทาครีมกันแดดซ้ำ | I | 16:57 (2 ชม. หลังกด) | 17:52 | ~55 นาที | ล็อกจอ (ภาพหน้าจอล็อก 17:57) |

- 15:18 ยังไม่ได้กด "เข้าร่มแล้ว" การ์ดบอก 126 % ของ MED · ผู้จัดทำคำนวณจากค่าบน (ชั่วโมง 14:00 และ 15:00) ได้ ≈ 255 J/m² ≈ 127 % ของ 200 J/m² ตรงกับการ์ด
- ทั้งสองรายการช้าแบบเดียวกับรอบ 2 (24–57 นาทีเมื่อล็อกจอ) ช่วงที่พบรวมทุกรอบตอนนี้คือ **21–57 นาที** · การตั้งแอปเป็น "ไม่พัก" ไม่ได้ทำให้ตรงเวลา จึงสนับสนุนสมมติฐานเดิมว่าเป็นการตั้งเวลาแบบไม่ตรงเวลา (ไม่มี `SCHEDULE_EXACT_ALARM`) ร่วมกับ Doze

## ข้อสังเกต
1. ใน Expo Go รุ่นใหม่ (SDK 58) เปิดโปรเจกต์ (SDK 57) ไม่ได้ ต้องใช้แอป development build ที่ติดตั้งไว้ · วันสอบอย่าอัปเดต Expo
2. ถ้าวันสอบเปลี่ยนเครือข่าย (เช่น Hotspot) IP ของโน้ตบุ๊กจะเปลี่ยน ต้องรัน API และ Expo ใหม่ด้วย IP ใหม่
3. แจ้งเตือนผิวไหม้ใช้เวลาออกแดดราว 20 นาทีและอาจช้า จึงใช้วิดีโอที่อัดไว้ในการนำเสนอ
4. ไม่มีบั๊กใหม่ ไม่มีการแก้โค้ด
