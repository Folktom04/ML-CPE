# UV Guard — แอป Expo

แอป React Native (Expo SDK 57, TypeScript, Expo Router) ของ UV Guard ข้อความที่ผู้ใช้เห็นเป็นภาษาไทยทั้งหมด

> ค่า UV, ระดับความเสี่ยง, เวลาผิวไหม้ และคำแนะนำเป็นค่าประมาณเพื่อการศึกษาและการเตือนเท่านั้น ไม่ใช่การวินิจฉัยทางการแพทย์

ตำแหน่ง (วัน 21): ใช้ GPS หรือจังหวัดที่เลือก ถ้ายังไม่ได้เลือกใช้ปทุมธานี โมเดลฝึกและทดสอบที่ปทุมธานีเท่านั้น ถ้าห่างเกิน 50 กม. API จะส่งหมายเหตุ "ความแม่นยำนอกพื้นที่ปทุมธานียังไม่ได้ประเมิน" มาแสดงบนการ์ด UV และนอกประเทศไทย API ตอบ 422 "รองรับเฉพาะพื้นที่ประเทศไทย"

## รัน
1. รัน API ที่ `Final-Project/` (ดู `docs/api.md`)
2. ในโฟลเดอร์นี้:
   ```powershell
   npm install
   copy .env.example .env   # ถ้าต้องเปลี่ยน EXPO_PUBLIC_API_URL
   npx expo start --web     # เปิด http://localhost:8081
   ```
- **มือถือจริง (Expo Go):** ตั้ง `EXPO_PUBLIC_API_URL=http://<IP ของคอมใน LAN>:8000` และรัน API ด้วย `--host 0.0.0.0` เพราะบนมือถือ `localhost` หมายถึงตัวมือถือเอง
- **CORS:** API อนุญาต `http://localhost:8081` และ `http://127.0.0.1:8081` เป็นค่าเริ่มต้น ถ้าจะใช้ origin อื่นให้ตั้ง `CORS_ORIGINS` ใน `.env` ของ API

## ทดสอบบนมือถือจริง (Expo Go)
ทดสอบแล้ว 28 ก.ย. 2026 บน Samsung (Android) กับ Expo Go หน้าหลักแสดง UVI, ช่วง q10–q90, UVA/UVB, เวลาผิวไหม้ และ disclaimer ถูกต้อง

1. **API ต้องฟังทุก interface:** รันจาก `Final-Project/`
   ```powershell
   $env:PYTHONPATH = "source_code"
   .venv\Scripts\python.exe -m uvicorn api.main:app --app-dir source_code --host 0.0.0.0 --port 8000
   ```
2. **หา IP ของคอมในวง LAN:** ใช้ `ipconfig` ดูที่ IPv4 Address เช่น `192.168.1.48` มือถือกับคอมต้องอยู่ Wi-Fi วงเดียวกัน
3. **ตรวจจากมือถือก่อน:** เปิด `http://<IP>:8000/health` ใน Chrome บนมือถือ ต้องได้ JSON ถ้าไม่ได้ แปลว่าปัญหาอยู่ที่เครือข่ายหรือ Windows Firewall ไม่ใช่ที่แอป
4. **ตั้ง URL ของ API ให้แอป** เลือกวิธีใดวิธีหนึ่ง:
   - ไฟล์ `source_code/app/.env.local` ใส่ `EXPO_PUBLIC_API_URL=http://<IP>:8000` (git ไม่เก็บไฟล์นี้)
   - หรือตั้งใน **หน้าต่าง PowerShell เดียวกัน**กับที่จะรัน Expo: `$env:EXPO_PUBLIC_API_URL="http://<IP>:8000"` ค่า `$env:` มีผลเฉพาะหน้าต่างนั้น และมีสิทธิ์ก่อนค่าในไฟล์ `.env*`
5. **รัน Expo:** `npx expo start --clear` แล้วสแกน QR ด้วย Expo Go
6. **ตรวจ:** ถ้าขึ้น "เชื่อมต่อเซิร์ฟเวอร์ไม่ได้" ให้ดูบรรทัด "ที่อยู่ที่เรียก" บนหน้าจอ ต้องเป็น `http://<IP>:8000/predict` ถ้ายังเป็น `localhost` แปลว่าแอปไม่ได้รับค่าจากข้อ 4

### เมื่อ Expo Go ใช้ bundle เก่า
อาการคือแก้ URL หรือแก้โค้ดแล้ว แต่ "ที่อยู่ที่เรียก" หรือหน้าจอยังเหมือนเดิม
1. ปิด Expo ทุกหน้าต่างบนคอม (Metro เก่าที่ยังค้างอาจทำให้ตัวใหม่ย้ายไปพอร์ต 8082 แต่มือถือยังเชื่อมกับตัวเก่า)
2. บนมือถือ (Android): **Settings → Apps → Expo Go → Force stop** แล้ว **Storage → Clear cache**
3. รัน `npx expo start --clear` ใหม่ แล้วสแกน QR ใหม่ (อย่าเปิดจากรายการ "Recently opened" ใน Expo Go)
4. ถ้ายังไม่หาย ใน Expo Go กด **Clear data** (ต้องสแกน QR ใหม่หลังจากนั้น)

ส่วน iOS: ปัดปิด Expo Go แล้วเปิดใหม่ ถ้ายังไม่หายให้ลบแอปแล้วติดตั้งใหม่

### ทดสอบกล้องและเซนเซอร์แสงบนมือถือจริง (วัน 20)
1. รัน API แบบในข้อ 1 ข้างบน แล้วดูหน้าต่างของ API ไปด้วย
2. หน้าหลัก → "ถ่ายท้องฟ้า": ครั้งแรกต้องขึ้นข้อความเรื่องการส่งภาพ กด "รับทราบ" แล้วออกและเข้าใหม่ ข้อความนั้นต้องไม่ขึ้นอีก
3. อนุญาตกล้อง หันขึ้นฟ้า (อย่าเล็งดวงอาทิตย์) กด "ถ่ายและวิเคราะห์" ต้องได้สภาพท้องฟ้า ความมั่นใจ และสัดส่วนเมฆ
4. **ตรวจ EXIF:** ในหน้าต่าง API ต้องมีบรรทัด `uvguard.api: sky-image upload has_exif=False` ทุกครั้งที่ถ่าย ถ้าเป็น `True` แปลว่ามีภาพหลุดไปโดยไม่ได้ re-encode ให้แจ้ง log เขียนแค่ boolean ไม่เขียนค่าของ EXIF
5. ปิด API แล้วถ่ายอีกครั้ง ต้องขึ้น "เชื่อมต่อเซิร์ฟเวอร์ไม่ได้" (ไฟล์ชั่วคราวยังถูกลบ ซึ่งตรวจไว้ในเทส Jest)
6. หน้าหลัก → "วัดแสง" (Android เท่านั้น):
   - วางหงายหน้าจอบนโต๊ะ ต้องขึ้น "ทิศทางถูกต้อง"
   - ยกขึ้นเอียงประมาณ 45° ต้องขึ้น "เอียงเกินไป"
   - คว่ำหน้าจอ ต้องขึ้น "หน้าจอคว่ำหรือตั้งอยู่"
   - ค่า lux ต้องเพิ่มเมื่อหันเข้าหาหน้าต่าง และลดลงเมื่อเอามือบังด้านบนของหน้าจอ

   **ถ้าวางหงายแล้วขึ้น "คว่ำ" แปลว่าเครื่องหมายแกน z ของเครื่องนี้ต่างจากที่คาดไว้** ให้แจ้ง (ดู `upZ()` ใน `src/lib/orientation.ts`)

## ทดสอบ flow ครบวงจรบนมือถือจริง (วัน 21)
ถ้าเคยเปิดแอปแล้ว ต้องล้างข้อมูลก่อน: หน้าตั้งค่า → "ลบข้อมูลของฉัน" หรือ Expo Go → Clear data และถ้าเคยอนุญาตตำแหน่งให้ Expo Go ไปแล้ว ให้ถอนสิทธิ์ใน Settings ของ Android ก่อนทดสอบกรณี "ไม่อนุญาต"
1. **อนุญาตตำแหน่ง:** เปิดแอป → ต้องไปหน้า "เริ่มต้นใช้งาน" ขั้นที่ 1/4 → "เริ่ม" → "ใช้ตำแหน่งปัจจุบัน (GPS)" → Android ถามสิทธิ์ ให้กด "ขณะใช้แอป" → ไปขั้นประเภทผิว → ทำแบบสอบถาม → กลับมาเห็น "ผิวประเภท …" → "ถัดไป" → สวิตช์ความยินยอมต้องปิดอยู่ และข้อความต้องบอก "ส่งแค่ชื่อจังหวัด ไม่ส่งพิกัด GPS" → "เริ่มใช้งาน" → หน้าหลักบรรทัดบนต้องเป็น "ตำแหน่งปัจจุบัน (GPS) · ใกล้ จ.… · ผิวประเภท …" (จังหวัดที่อยู่จริง) และค่า UV ต้องขึ้น
2. **ไม่อนุญาตตำแหน่ง:** ล้างข้อมูลแล้วทำซ้ำ แต่ตอนถามสิทธิ์ให้กด "ไม่อนุญาต" → ต้องขึ้น "ไม่ได้รับสิทธิ์ตำแหน่ง เลือกจังหวัดแทนได้" และเปิดหน้าเลือกจังหวัด → ค้น "เชียง" → เลือกเชียงใหม่ → กลับมาเห็น "จ.เชียงใหม่ (เลือกเอง)" → ทำขั้นที่เหลือให้จบ → หน้าหลักต้องเป็น "จ.เชียงใหม่ (เลือกเอง)" และการ์ด UV ต้องมีหมายเหตุ "ความแม่นยำนอกพื้นที่ปทุมธานียังไม่ได้ประเมิน"
3. **ถอนสิทธิ์ทีหลัง:** ตั้งค่า GPS แล้วไปถอนสิทธิ์ตำแหน่งของ Expo Go ใน Settings ของ Android → กลับมาลากลงเพื่อโหลดใหม่ → ต้องขึ้น "ไม่ได้รับสิทธิ์ตำแหน่ง จึงใช้จ.… แทน" และแอปยังใช้งานได้
4. **ปิด GPS ของเครื่อง:** ต้องขึ้น "หาตำแหน่งปัจจุบันไม่ได้ …" ภายใน ~10 วินาที ไม่ค้าง

## ทดสอบการแจ้งเตือนบนมือถือจริง (วัน 22)
**Android ต้องใช้ development build (EAS Build) ไม่ใช่ Expo Go:** ใน `expo-notifications` 57.0.21 แค่ import ก็ throw บน Expo Go Android ("…removed from Expo Go with the release of SDK 53") แอปจึงไม่โหลดโมดูลนี้ใน Expo Go Android และปิดฟีเจอร์แจ้งเตือน (แก้ 29 ก.ย. 2026 ดู ROADMAP วัน 22) iOS ใช้ Expo Go ได้ ให้อนุญาตการแจ้งเตือนตอนถูกถาม

0. **Expo Go บน Android (ตรวจว่าไม่พัง):** เปิดแอปต้องเข้าหน้าหลักได้ตามปกติ หน้าตั้งค่าต้องขึ้น "Expo Go บน Android ไม่รองรับการแจ้งเตือน … ต้องใช้ development build" สวิตช์แจ้งเตือนเป็นสีเทากดไม่ได้ การ์ด "อยู่กลางแจ้ง" กด "ออกแดด" แล้วต้องขึ้น "จะถึงประมาณ 80 % ของ MED ราว HH:MM (ไม่มีแจ้งเตือนเด้ง ดูที่หน้านี้)" และเมื่อเปิดด้วย development build ภายหลัง สวิตช์ต้องกลับมาเป็นค่าที่เคยตั้งไว้
1. **เตือน UV:** ตั้งค่า → เกณฑ์ "สูง (6+)" ตอนเช้าที่พยากรณ์บอกว่าอีก 1–2 ชม. UV ถึง 6 แล้วเปิดหน้าหลักค้างไว้ให้โหลดเสร็จ จากนั้นล็อกจอรอ ต้องได้ "UV สูง ช่วง HH:00–HH:00 …" ตอนต้นชั่วโมงนั้น **จดเวลาที่ได้รับจริง เทียบกับเวลาต้นชั่วโมง แล้วบันทึกว่าช้ากี่นาที** (Android Doze อาจทำให้ช้า) ทดสอบทั้งตอนเสียบสายชาร์จและไม่เสียบ
2. **ปลอดภัยแล้ว:** ช่วงบ่ายเมื่อค่าบนลดต่ำกว่าเกณฑ์ − 2 ต้องได้ "UV ลดลงแล้ว …" 1 ครั้ง ไม่เกิน 1 ครั้งต่อ 3 ชม. และไม่มีแจ้งเตือนหลังพระอาทิตย์ตก
3. **สรุป 07:00:** เปิดแอปตอนเย็น แล้วเช้าวันถัดไปต้องได้ "UV วันนี้สูงสุดประมาณ …" ตอน 07:00 (จดว่าช้ากี่นาที) ถ้าไม่ได้เปิดแอปเกิน 1 วัน ต้องได้ "เปิดแอปเพื่อดู UV วันนี้" แทน
4. **ออกแดด:** กลางวันกด "ออกแดด" แล้วดูว่ามีข้อความ "จะเตือนราว HH:MM" และคำอธิบาย "คิดจากกรณีอยู่กลางแดดเต็มที่ …" ปิดแอปรอจนถึงเวลานั้น ต้องได้ "ใกล้ถึงเวลาผิวไหม้ (ประมาณ)" (จดว่าช้ากี่นาที) กด "เข้าร่มแล้ว" แล้วต้องไม่มีแจ้งเตือนนี้อีก
5. **ทาครีมแล้ว:** กดแล้วต้องขึ้น "จะเตือนทาครีมซ้ำราว …" (อีก 2 ชม.) และได้รับแจ้งเตือนตอนนั้น ถ้ากดหลัง ~16:30 ต้องขึ้นว่าไม่ตั้งเตือนเพราะเลยช่วงมีแดดแล้ว
6. **ไม่อนุญาตแจ้งเตือน:** ปิดสิทธิ์แจ้งเตือนของ Expo Go ใน Settings ของ Android → หน้าตั้งค่าและการ์ด "อยู่กลางแจ้ง" ต้องบอก "ยังไม่ได้อนุญาตการแจ้งเตือน" และแอปยังดูค่าได้ตามปกติ
7. **ลบข้อมูลของฉัน:** ต้องไม่มีแจ้งเตือนที่ตั้งไว้เด้งขึ้นมาอีก

## รายการตรวจหน้าจอ (สำหรับ browser agent ของ Antigravity)
เปิด `npx expo start --web` โดยให้ API รันอยู่ แล้วตรวจ:
1. หัวข้อ "UV Guard" และบรรทัด "ปทุมธานี (ตำแหน่งเริ่มต้น) · ผิวประเภท III"
2. การ์ด UV: ตัวเลข UVI ใหญ่ ป้ายระดับเป็นภาษาไทย สีป้ายตรง WHO (ต่ำ #3E9B4F, ปานกลาง #D9A400 ตัวอักษรสีเข้ม, สูง #E36B12, สูงมาก #D22F3A, รุนแรงมาก #8A3FC2) และมีบรรทัดช่วง q10–q90
3. ถ้าระดับ q90 สูงกว่าระดับที่แสดง ต้องมีแถบ "เตือนตามค่าบน (q90) …"
4. การ์ด UVA/UVB มีหน่วย W/m² และเวลาก่อนผิวไหม้ ถ้าเป็นกลางคืนต้องขึ้น "ไม่มีความเสี่ยง (กลางคืน)" ต้องไม่มีคำแนะนำ (เช่น "ใส่แว่นกันแดด") และต้องมีกล่อง "พรุ่งนี้ / วันนี้ UV สูงสุดประมาณ …"
5. ปิด API แล้วโหลดหน้าใหม่: ต้องขึ้น "เชื่อมต่อเซิร์ฟเวอร์ไม่ได้ …" พร้อมปุ่ม "ลองใหม่" และ disclaimer ยังอยู่ท้ายหน้า
6. ความกว้างแบบมือถือ (375 px) ต้องไม่มี scroll แนวนอน (ยกเว้นในกราฟรายชั่วโมง ซึ่งเลื่อนแนวนอนได้เอง)
7. กราฟรายชั่วโมง (วัน 19): แท่งสีตามระดับ WHO, เส้นช่วงสีเทาเข้ม, มีตัวเลขเฉพาะแท่งสูงสุด, แตะแท่งแล้วบรรทัดบนกราฟเปลี่ยนเป็นชั่วโมงนั้นและมีจุดใต้แกนตรงชั่วโมงที่เลือก (ต้องไม่มีพื้นหลังเทาสูงเต็มกราฟ), ถ้าเปิดตอนกลางคืน กราฟต้องเลื่อนไปและเลือกชั่วโมงสูงสุดของวันถัดไป ("พรุ่งนี้ …"), มีคำอธิบายสีระดับ 5 สีใต้กราฟ, ชั่วโมงกลางคืนเป็นขีดเทาเตี้ย ๆ
8. ปุ่ม "ตั้งค่า" มุมขวาบน → หน้าตั้งค่า: เลือกระดับเตือน 6 / 8 / 11 แล้วข้อความเปลี่ยนเป็น "ต่ำกว่า 4 / 6 / 9", สวิตช์ความยินยอม (การ์ดเหนือการแจ้งเตือน) ปิดอยู่ตั้งแต่แรก, บรรทัดสถานะบอก "เก็บในเครื่องเท่านั้น" และสวิตช์ "เปิดการแจ้งเตือน" กดไม่ได้พร้อมป้าย "ยังไม่ทำงาน ต้องยินยอมให้ส่งข้อมูลก่อน"
9. "ทำแบบสอบถามประเภทผิว": ผลขึ้นเมื่อตอบครบ 5 ข้อ มีข้อความ "แบบย่อดัดแปลงจาก Fitzpatrick ยังไม่ผ่านการตรวจสอบทางวิชาการ" กด "ใช้ประเภทผิวนี้" แล้วกลับหน้าหลัก บรรทัดบนสุดต้องเปลี่ยนเป็นประเภทใหม่ และตัวเลขเวลาผิวไหม้ต้องเปลี่ยนตาม
10. "ลบข้อมูลของฉัน" ต้องมีหน้ายืนยันก่อน กด "ยกเลิก" แล้วไม่มีอะไรถูกลบ
11. หน้าหลักมีการ์ด "ดูเพิ่มเติม" และปุ่ม "ถ่ายท้องฟ้า" บนเว็บต้อง**ไม่มี**ปุ่ม "วัดแสง" (Android เท่านั้น) และเปิด `/light` ตรงๆ ต้องขึ้น "ใช้ได้เฉพาะ Android"
12. "ถ่ายท้องฟ้า" ครั้งแรกต้องขึ้น "ภาพจะถูกส่งไปวิเคราะห์ที่เซิร์ฟเวอร์แล้วลบทันที ไม่มีการเก็บภาพ" พร้อมปุ่ม "รับทราบ" กดแล้วโหลดหน้าใหม่ ข้อความต้องไม่ขึ้นอีก ถ้าเบราว์เซอร์ถามสิทธิ์กล้องแล้วกดไม่อนุญาต ต้องขึ้น "ต้องใช้สิทธิ์กล้อง" และหน้าหลักยังใช้ได้
