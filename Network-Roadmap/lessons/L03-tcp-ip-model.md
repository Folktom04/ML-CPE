# บทเรียน Level 3 — TCP/IP Model (ฉบับละเอียด)

> อ่านจบแล้วจะ: รู้จักโมเดลที่อินเทอร์เน็ตใช้จริง · map กับ OSI ได้ · รู้จักองค์กรมาตรฐาน (IETF, IEEE, IANA) และ RFC · เห็นการเดินทางของข้อมูลจริงผ่านแต่ละชั้น

---

## 1. TCP/IP Model คืออะไร

**TCP/IP Model** (หรือ Internet Protocol Suite) คือ **ชุดโปรโตคอลที่อินเทอร์เน็ตใช้งานจริง** พัฒนาขึ้นจากโครงการ ARPANET ของกระทรวงกลาโหมสหรัฐฯ ในทศวรรษ 1970 และใช้อย่างเป็นทางการตั้งแต่ปี 1983 ตั้งชื่อตามสองโปรโตคอลหลักคือ **TCP** และ **IP**

| | OSI | TCP/IP |
|---|---|---|
| ลักษณะ | โมเดลอ้างอิงเชิงทฤษฎี | โมเดลของโปรโตคอลที่ใช้จริง |
| จำนวนชั้น | 7 | 4 (บางตำราแบ่ง 5) |
| ใช้ทำอะไร | สอน, สื่อสาร, troubleshoot | อินเทอร์เน็ตและเครือข่ายทั้งหมดในปัจจุบัน |

---

## 2. 4 ชั้นของ TCP/IP และการ map กับ OSI

```
        OSI (7)                     TCP/IP (4)             TCP/IP (5 ชั้นแบบสมัยใหม่)
 ┌───────────────────┐       ┌─────────────────────┐     ┌──────────────────┐
 │ 7 Application      │       │                     │     │                  │
 │ 6 Presentation     │  ───► │   Application       │     │ 5 Application    │
 │ 5 Session          │       │                     │     │                  │
 ├───────────────────┤       ├─────────────────────┤     ├──────────────────┤
 │ 4 Transport        │  ───► │   Transport         │     │ 4 Transport      │
 ├───────────────────┤       ├─────────────────────┤     ├──────────────────┤
 │ 3 Network          │  ───► │   Internet          │     │ 3 Network        │
 ├───────────────────┤       ├─────────────────────┤     ├──────────────────┤
 │ 2 Data Link        │  ───► │   Network Access    │     │ 2 Data Link      │
 │ 1 Physical         │       │   (Link)            │     │ 1 Physical       │
 └───────────────────┘       └─────────────────────┘     └──────────────────┘
```

### ชั้น Application
- รวมหน้าที่ของ OSI L5–L7 ไว้ด้วยกัน
- **โปรโตคอล:** HTTP/HTTPS, DNS, DHCP, SMTP, IMAP, POP3, FTP, SSH, Telnet, SNMP, NTP, RDP
- แอปพลิเคชันจัดการรูปแบบข้อมูล การเข้ารหัส และ session เอง (เช่น HTTP + TLS)

### ชั้น Transport
- ส่งข้อมูลระหว่าง **process** (แอปพลิเคชัน) บนสองเครื่อง แยกด้วย **port**
- **TCP:** connection-oriented, เชื่อถือได้ (เว็บ, อีเมล, ไฟล์)
- **UDP:** connectionless, เร็ว (DNS, VoIP, วิดีโอสด, เกม)
- **QUIC:** โปรโตคอลรุ่นใหม่ที่ทำงานบน UDP ใช้กับ HTTP/3

### ชั้น Internet
- กำหนด **ที่อยู่ (IP)** และ **การเลือกเส้นทาง** ข้ามเครือข่าย
- **โปรโตคอล:** IPv4, IPv6, ICMP, (ARP ทำงานคาบเกี่ยวกับชั้นล่าง), IPsec, routing protocol (OSPF, BGP)
- IP เป็น **best effort**: พยายามส่ง แต่ไม่รับประกันว่าถึง/ครบ/เรียง (หน้าที่นั้นเป็นของ TCP)

### ชั้น Network Access (Link)
- การส่งบนสื่อกลางจริงภายในเครือข่ายเดียว
- **เทคโนโลยี:** Ethernet, Wi-Fi, PPP, เซลลูลาร์ (4G/5G), ไฟเบอร์
- TCP/IP **ไม่ได้กำหนดรายละเอียดชั้นนี้เอง** แต่ใช้มาตรฐานจากองค์กรอื่น (เช่น IEEE)

> 💡 **รูปทรง "นาฬิกาทราย":** ด้านบนมีแอปนับพัน ด้านล่างมีเทคโนโลยีการเชื่อมต่อนับสิบ แต่ตรงกลางมี **IP เพียงตัวเดียว** ที่ทุกอย่างต้องผ่าน นี่คือเหตุผลที่อินเทอร์เน็ตเชื่อมทุกอย่างได้
>
> ```
>  HTTP  DNS  SMTP  SSH  RTP  ...   (Application นับพัน)
>        TCP   UDP   QUIC            (Transport)
>               IP                   ← คอคอดเดียว
>   Ethernet  Wi-Fi  5G  Fiber ...   (Link หลากหลาย)
> ```

## 3. ตัวอย่าง: เปิดเว็บไซต์ผ่านแต่ละชั้น

ผู้ใช้เปิด `https://www.example.com` จากโน้ตบุ๊กที่ต่อ Wi-Fi บ้าน

| ชั้น | สิ่งที่เกิดขึ้น |
|---|---|
| **Application** | browser ถาม **DNS** ว่า www.example.com มี IP อะไร → ได้ IP แล้วสร้างคำขอ **HTTP GET** (ห่อด้วย TLS) |
| **Transport** | **TCP** ทำ 3-way handshake ไปที่ port **443** ฝั่งเราใช้ port สุ่ม เช่น 51544 |
| **Internet** | ใส่ **IP header**: ต้นทาง 192.168.1.20 → ปลายทาง 93.184.x.x, ตัดสินใจว่าปลายทางอยู่นอกวง จึงส่งให้ default gateway |
| **Network Access** | ใช้ **ARP** หา MAC ของ router บ้าน แล้วส่ง frame ผ่าน **Wi-Fi** ไปยัง router |
| (ระหว่างทาง) | router บ้านทำ NAT แล้วส่งต่อผ่าน ISP และ router อินเทอร์เน็ตหลายสิบตัวจนถึง server |
| **ฝั่ง server** | แกะทีละชั้นขึ้นไปจนถึงเว็บเซิร์ฟเวอร์ ซึ่งส่งหน้าเว็บกลับมาในเส้นทางย้อนกลับ |

## 4. องค์กรมาตรฐานที่ต้องรู้จัก

| องค์กร | ดูแลอะไร | ตัวอย่าง |
|---|---|---|
| **IETF** (Internet Engineering Task Force) | มาตรฐานโปรโตคอลอินเทอร์เน็ต ผ่านเอกสาร **RFC** | IP, TCP, HTTP, DNS, BGP |
| **IEEE** (Institute of Electrical and Electronics Engineers) | มาตรฐานชั้นกายภาพ/Data Link | **802.3** Ethernet, **802.11** Wi-Fi, **802.1Q** VLAN, **802.1X** |
| **IANA** (Internet Assigned Numbers Authority) | แจกจ่ายตัวเลขสำคัญระดับโลก | IP address block, **port number**, root DNS |
| **RIR** (Regional Internet Registry) | แจก IP/ASN ระดับภูมิภาค (รับต่อจาก IANA) | **APNIC** (เอเชียแปซิฟิก รวมไทย), ARIN, RIPE NCC |
| **ICANN** | กำกับดูแล IANA, ระบบโดเมนระดับบน | .com, .th (ดูแลโดย THNIC) |
| **ISO** | มาตรฐานสากลทั่วไป | OSI Model, ISO 27001 |
| **W3C** | มาตรฐานเว็บ | HTML, CSS |

### RFC (Request for Comments) คืออะไร
- เอกสารมาตรฐาน/ข้อกำหนดของอินเทอร์เน็ต มีเลขกำกับ เผยแพร่ฟรีที่ rfc-editor.org
- **RFC ที่ควรรู้จัก:** RFC 791 (IPv4), RFC 9293 (TCP ฉบับปรับปรุง), RFC 768 (UDP), RFC 1918 (Private IP), RFC 2131 (DHCP), RFC 1034/1035 (DNS), RFC 8200 (IPv6), RFC 9110 (HTTP semantics)
- คำว่า **MUST / SHOULD / MAY** ใน RFC มีความหมายเฉพาะ (RFC 2119): MUST = บังคับ, SHOULD = ควรทำเว้นแต่มีเหตุผล, MAY = ทำก็ได้ไม่ทำก็ได้

---

## 5. ทำไมยังใช้คำของ OSI ในงานจริง

แม้ระบบจะทำงานแบบ TCP/IP แต่ในงานจริงยังพูดว่า "Layer 2/3/4/7" ตาม OSI เพราะ
- ละเอียดกว่า แยก L1 กับ L2 ได้ (สายเสีย vs VLAN ผิด เป็นปัญหาคนละแบบ)
- เป็นภาษาที่ผู้ผลิตและเอกสาร vendor ใช้กันทั่วโลก
- ใช้เป็นกรอบในการไล่ปัญหา

---

## 6. เรื่องที่คนมักเข้าใจผิด

| ❌ | ✅ |
|---|---|
| TCP/IP คือ 2 โปรโตคอล | คือ **ชุด** โปรโตคอลหลายสิบตัว ตั้งชื่อตามสองตัวหลัก |
| OSI กับ TCP/IP แข่งกัน ต้องเลือกใช้อันเดียว | TCP/IP คือของที่ใช้จริง OSI คือกรอบอธิบาย ใช้ร่วมกันได้ |
| IP รับประกันว่าข้อมูลถึง | IP เป็น best effort; TCP เป็นผู้รับประกัน |
| ใคร ๆ ก็ตั้ง IP สาธารณะเองได้ | ต้องได้รับจัดสรรผ่าน ISP หรือ RIR (APNIC) |

## 7. Cheat Sheet

```
TCP/IP 4 ชั้น         ↔ OSI
Application           ↔ L5-L7   HTTP DNS DHCP SMTP SSH SNMP NTP
Transport             ↔ L4      TCP (เชื่อถือได้)  UDP (เร็ว)  QUIC
Internet              ↔ L3      IPv4 IPv6 ICMP · best effort
Network Access/Link   ↔ L1-L2   Ethernet Wi-Fi 5G · มาตรฐานจาก IEEE

IETF = RFC/โปรโตคอล · IEEE = 802.x · IANA = IP/port/DNS root · APNIC = RIR ของไทย
IP คือคอคอดของนาฬิกาทราย: ทุกแอปและทุกสื่อกลางเจอกันที่ IP
```

## 8. แบบทดสอบ 10 ข้อ

1. TCP/IP Model มีกี่ชั้น อะไรบ้าง
2. OSI Layer 5, 6, 7 รวมอยู่ในชั้นใดของ TCP/IP
3. ICMP อยู่ชั้นใดของ TCP/IP
4. องค์กรใดกำหนดมาตรฐาน Wi-Fi
5. องค์กรใดแจก IP ให้ประเทศไทย
6. เอกสาร RFC คืออะไร หาอ่านได้ที่ไหน
7. ทำไมเรียก IP ว่า best effort และใครทำให้ข้อมูลส่งครบ
8. ในโมเดล 5 ชั้นแบบสมัยใหม่ ชั้นใดที่แยกออกจาก Network Access
9. ตอนเปิดเว็บ ชั้นใดเลือก port 443
10. ทำไมอินเทอร์เน็ตรองรับเทคโนโลยีการเชื่อมต่อใหม่ ๆ (เช่น 5G) ได้โดยไม่ต้องแก้ทุกแอป
