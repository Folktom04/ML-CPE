# บทเรียน Level 10 — VLSM, CIDR & Route Summarization (ฉบับละเอียด)

> อ่านจบแล้วจะ: วางแผน IP แบบ VLSM ไม่ให้สิ้นเปลืองและไม่ซ้อนกัน · สรุป (summarize) หลาย subnet เป็น route เดียวได้ · ออกแบบ IP plan ระดับองค์กรที่ขยายได้

---

## 1. ปัญหาของการแบ่ง subnet ขนาดเท่ากัน (FLSM)

บริษัทมีความต้องการ: ฝ่ายขาย 100 คน, บัญชี 50, HR 20, ลิงก์ WAN 2 เส้น (เส้นละ 2 IP)

ถ้าแบ่ง 192.168.10.0/24 แบบ **ขนาดเท่ากัน (FLSM)** ต้องใช้ขนาดที่ใหญ่พอสำหรับฝ่ายขาย (/25 = 126 host) ทุกวง → /24 แบ่ง /25 ได้แค่ **2 วง ไม่พอ 5 วง** และลิงก์ WAN ที่ต้องการแค่ 2 IP ก็กิน 126 IP

**VLSM (Variable Length Subnet Mask)** = แบ่งวงให้ **ขนาดต่างกันตามความต้องการจริง**

---

## 2. ขั้นตอนทำ VLSM

1. **เรียงความต้องการจากมากไปน้อย** (สำคัญมาก เพื่อไม่ให้วงซ้อนหรือมีช่องว่างที่ใช้ไม่ได้)
2. เลือก prefix ที่เล็กที่สุดที่ยังพอสำหรับแต่ละความต้องการ
3. จัดสรรต่อกันไปทีละวง วงใหม่เริ่มต่อจาก broadcast ของวงก่อน (+1) และต้องเริ่มที่ผลคูณของ block size ของตัวเอง
4. บันทึกเป็นตาราง

### ตัวอย่างเต็ม: 192.168.10.0/24

| ลำดับ | ความต้องการ | host | Prefix | Block | Network | ช่วง host | Broadcast |
|---|---|---|---|---|---|---|---|
| 1 | ฝ่ายขาย | 100 | /25 | 128 | 192.168.10.0 | .1 – .126 | .127 |
| 2 | บัญชี | 50 | /26 | 64 | 192.168.10.128 | .129 – .190 | .191 |
| 3 | HR | 20 | /27 | 32 | 192.168.10.192 | .193 – .222 | .223 |
| 4 | WAN-1 | 2 | /30 | 4 | 192.168.10.224 | .225 – .226 | .227 |
| 5 | WAN-2 | 2 | /30 | 4 | 192.168.10.228 | .229 – .230 | .231 |
| — | **ว่างสำรอง** | | | | 192.168.10.232 – .255 | | |

```
 0                  128          192     224 228 232          255
 |──── ขาย /25 ─────|── บัญชี /26 ─|─HR /27─|W1|W2|── ว่าง ────|
```

> ⚠️ **ถ้าไม่เรียงจากใหญ่ไปเล็ก** เช่น จัด HR /27 ไว้ที่ .0 ก่อน ฝ่ายขาย /25 จะต้องเริ่มที่ .128 (ผลคูณของ 128) ทำให้ .32–.127 ใช้ได้แค่วงเล็ก ๆ และอาจไม่พอสำหรับบัญชี

## 3. CIDR (Classless Inter-Domain Routing)

- เลิกผูกขนาดเครือข่ายกับ Class A/B/C ใช้ **prefix length อิสระ** (/0 ถึง /32)
- ทำให้ ISP แจก IP ได้ขนาดพอดีกับลูกค้า (เช่น /29 = 8 IP) และ **สรุป route ได้**
- รูปแบบเขียน `network/prefix` เช่น `203.0.113.0/24`

---

## 4. Route Summarization (Supernetting / Aggregation)

**แนวคิด:** รวมหลาย subnet ที่อยู่ติดกันเป็น **route เดียวที่ครอบทั้งหมด**

```
 สาขา A มี:  10.1.0.0/24
            10.1.1.0/24          router สำนักงานใหญ่เห็นแค่
            10.1.2.0/24    ═══►  10.1.0.0/22  (route เดียว)
            10.1.3.0/24
```

**ประโยชน์:**
- **Routing table เล็กลง** → router ใช้ memory/CPU น้อยลง ค้นหาเร็วขึ้น
- **เสถียรกว่า:** ถ้า subnet ย่อยวงหนึ่งขึ้นลง (flap) router ที่อยู่ไกลออกไปไม่ต้องคำนวณใหม่
- **จัดการง่าย:** ACL/firewall เขียน rule ครั้งเดียวครอบทั้งสาขา

### วิธีหา Summary Route — หา "บิตที่เหมือนกัน" จากซ้าย

**โจทย์: สรุป 172.16.8.0/24 ถึง 172.16.15.0/24**
```
 octet 3 ของแต่ละวง:
  8 = 0000 1000
  9 = 0000 1001
 10 = 0000 1010
  ...
 15 = 0000 1111
      └─┬─┘
      5 บิตแรกเหมือนกัน (00001)

 บิตที่เหมือนกัน = 16 (octet 1-2) + 5 = 21 → /21
 network = บิตเหมือนกัน + ที่เหลือเป็น 0 = 0000 1000 = 8
 Summary = 172.16.8.0/21
```

**ทางลัด:** จำนวนวง /24 ที่ติดกันเป็น 2ⁿ และวงแรกเป็นผลคูณของ 2ⁿ → summary = /(24 − n)
- 4 วง (10.1.0–3) → n=2 → **/22**
- 8 วง (172.16.8–15) → n=3 → **/21** (และ 8 หาร 8 ลงตัว ✅)

### ⚠️ ระวัง: Summary ที่ไม่สมบูรณ์

**โจทย์: สรุป 10.1.4.0/24, 10.1.5.0/24, 10.1.6.0/24** (3 วง ไม่ใช่ 2ⁿ)
- สรุปเป็น 10.1.4.0/22 จะครอบ 10.1.4–**10.1.7** ซึ่ง **10.1.7.0 ไม่มีอยู่จริงที่สาขานี้**
- ถ้า 10.1.7.0 อยู่ที่อื่น traffic จะถูกดึงมาผิดที่ (**blackhole** หรือ routing loop)
- **แก้:** สรุปเฉพาะส่วนที่สมบูรณ์ หรือใส่ **null route** (`ip route 10.1.4.0 255.255.252.0 Null0`) ที่ router สาขา เพื่อทิ้ง traffic ที่ไปวงที่ไม่มีอยู่จริงแทนการส่งวนไปมา

## 5. /30 vs /31 สำหรับลิงก์ point-to-point

| | /30 | /31 |
|---|---|---|
| IP ทั้งหมด | 4 | 2 |
| ใช้ได้ | 2 (หัก network/broadcast) | 2 (ทั้งคู่ ตาม RFC 3021) |
| ประหยัด | น้อยกว่า | ประหยัดกว่าครึ่ง |
| รองรับ | ทุกอุปกรณ์ | อุปกรณ์รุ่นใหม่ส่วนใหญ่ (ตรวจก่อนใช้) |
| ใช้ที่ไหน | ทั่วไป | Data Center/ISP ที่มีลิงก์จำนวนมาก |

## 6. ออกแบบ IP Plan ระดับองค์กร (แนวปฏิบัติจริง)

**หลักการ**
1. **ให้ summarize ได้:** แต่ละสาขา/อาคารได้ block ต่อเนื่องหนึ่งก้อน
2. **อ่านแล้วเข้าใจ:** ให้ตัวเลขสื่อความหมาย (เช่น octet ที่ 2 = สาขา, octet ที่ 3 = VLAN)
3. **เผื่อขยาย:** สำรองไว้อย่างน้อย 30–50%
4. **ไม่ใช้ช่วงที่มักชนกัน:** หลีกเลี่ยง 192.168.0.0/24 และ 192.168.1.0/24 (ชนกับ router บ้านเวลาผู้ใช้ VPN เข้ามา) และระวังวงที่ Docker/cloud ใช้เป็นค่าเริ่มต้น
5. **บันทึกใน IPAM** (spreadsheet หรือ NetBox)

**ตัวอย่างโครงสร้าง**
```
 10.0.0.0/8  ทั้งองค์กร
 ├─ 10.0.0.0/16    Data Center
 │   ├─ 10.0.10.0/24  Server VLAN 10
 │   └─ 10.0.20.0/24  Storage VLAN 20
 ├─ 10.1.0.0/16    สำนักงานใหญ่
 │   ├─ 10.1.10.0/24  Users ชั้น 1 (VLAN 10)
 │   ├─ 10.1.20.0/24  Voice (VLAN 20)
 │   └─ 10.1.99.0/24  Management (VLAN 99)
 ├─ 10.11.0.0/16   สาขาเชียงใหม่   ← router HQ เห็นแค่ 10.11.0.0/16
 ├─ 10.12.0.0/16   สาขาขอนแก่น
 └─ 10.255.0.0/16  ลิงก์ WAN /30 /31
```
> 💡 เห็น IP `10.12.20.35` ก็รู้ทันทีว่าเป็นอุปกรณ์ voice ที่สาขาขอนแก่น

## 7. ตรวจด้วย Python

```python
import ipaddress
nets = [ipaddress.ip_network(f"172.16.{i}.0/24") for i in range(8, 16)]
print(list(ipaddress.collapse_addresses(nets)))   # [IPv4Network('172.16.8.0/21')]
```

## 8. เรื่องที่คนมักเข้าใจผิด

| ❌ | ✅ |
|---|---|
| VLSM จัดลำดับไหนก็ได้ | ต้องเรียงจากใหญ่ไปเล็ก ไม่งั้นเกิดช่องว่าง/วงซ้อน |
| สรุป route ให้กว้างที่สุดเท่าที่ทำได้เสมอ | กว้างเกินจะครอบวงที่ไม่มีอยู่จริง → blackhole |
| วงไหนก็สรุปรวมกันได้ | ต้องติดกันและวงแรกต้องอยู่ตรงขอบของ block ที่สรุป |

## 9. Cheat Sheet

```
VLSM: เรียงใหญ่ → เล็ก · prefix เล็กสุดที่พอ · เริ่มที่ผลคูณ block · บันทึกตาราง
Summary: หาบิตเหมือนกันจากซ้าย · 2^n วงติดกัน (เริ่มที่ผลคูณ 2^n) → /(24−n)
4 วง /24 → /22 · 8 วง → /21 · 16 วง → /20
ระวัง summary ครอบวงที่ไม่มีจริง → ใส่ Null0 route
P2P: /30 (2 host) หรือ /31 (RFC 3021)
IP plan: summarize ได้ · มีความหมาย · เผื่อ 30-50% · เลี่ยง 192.168.0/1.x · ใช้ IPAM
```

## 10. แบบทดสอบ 10 ข้อ

1. VLSM ต่างจาก FLSM อย่างไร
2. ทำไมต้องเรียงความต้องการจากมากไปน้อย
3. จาก 10.10.0.0/24 จัด VLSM ให้: A 60 host, B 28 host, C 12 host, ลิงก์ 2 เส้น
4. สรุป 10.1.0.0/24 – 10.1.3.0/24
5. สรุป 192.168.16.0/24 – 192.168.31.0/24
6. 10.5.4.0/24, 10.5.5.0/24, 10.5.6.0/24 ถ้าสรุปเป็น /22 มีความเสี่ยงอะไร
7. ประโยชน์ของ route summarization 3 ข้อ
8. /31 ใช้ที่ไหน ต่างจาก /30 อย่างไร
9. ทำไมไม่ควรใช้ 192.168.1.0/24 ใน LAN องค์กร
10. ออกแบบอย่างไรให้ router สำนักงานใหญ่เห็นแค่ 1 route ต่อสาขา
