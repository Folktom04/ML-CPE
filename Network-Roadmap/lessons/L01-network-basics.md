## 1. Network คืออะไร

### นิยาม

> **เครือข่ายคอมพิวเตอร์ (Computer Network)** คือ อุปกรณ์ตั้งแต่ **2 ตัวขึ้นไป** ที่เชื่อมต่อกัน เพื่อ **แลกเปลี่ยนข้อมูล** และ **ใช้ทรัพยากรร่วมกัน**

ตัวอย่างที่ง่ายที่สุดคือ คอมพิวเตอร์ 2 เครื่องต่อสาย LAN ถึงกันแล้วส่งไฟล์ให้กันได้ ซึ่งก็นับเป็นเครือข่ายแล้ว ส่วนตัวอย่างที่ใหญ่ที่สุดคือ **อินเทอร์เน็ต** ซึ่งเป็นเครือข่ายของเครือข่ายนับล้านทั่วโลก

### ทำไมต้องมีเครือข่าย

| ประโยชน์ | ตัวอย่างในชีวิตจริง |
|---|---|
| **แชร์ข้อมูล** | ส่งไฟล์งาน, เปิดโฟลเดอร์กลางของแผนก, ฐานข้อมูลลูกค้าที่ทุกคนใช้ร่วมกัน |
| **แชร์ทรัพยากร** | เครื่องพิมพ์ 1 เครื่องใช้ได้ทั้งแผนก, อินเทอร์เน็ต 1 เส้นใช้ทั้งบ้าน, server/storage กลาง |
| **สื่อสาร** | อีเมล, แชท, วิดีโอคอล, โทรศัพท์ VoIP |
| **จัดการจากศูนย์กลาง** | IT ติดตั้งโปรแกรม/อัปเดต/สำรองข้อมูลให้ทุกเครื่องจากที่เดียว |
| **ลดต้นทุน** | ไม่ต้องซื้อเครื่องพิมพ์หรืออินเทอร์เน็ตแยกให้ทุกคน |

### องค์ประกอบของเครือข่าย

เครือข่ายทุกขนาด ตั้งแต่ในบ้านจนถึงอินเทอร์เน็ต มีองค์ประกอบ 4 อย่างเหมือนกัน

```
 [อุปกรณ์ปลายทาง] ──สื่อกลาง── [อุปกรณ์เครือข่าย] ──สื่อกลาง── [อุปกรณ์ปลายทาง]
        PC/มือถือ          สาย/คลื่น      Switch/Router          สาย/คลื่น       Server/Printer
                         ทุกตัวคุยกันด้วย "กติกาเดียวกัน" = Protocol
```

1. **อุปกรณ์ปลายทาง (End Devices / Hosts)** — ต้นทางหรือปลายทางของข้อมูล เช่น คอมพิวเตอร์, มือถือ, server, เครื่องพิมพ์, กล้อง IP, Smart TV
2. **อุปกรณ์เครือข่าย (Intermediary Devices)** — ตัวกลางที่ส่งต่อข้อมูล เช่น
   - **Switch**: เชื่อมอุปกรณ์ในเครือข่ายเดียวกัน (ภายในบ้าน/ชั้น/อาคาร)
   - **Router**: เชื่อม *ระหว่าง* เครือข่าย (เช่น บ้าน ↔ อินเทอร์เน็ต)
   - **Access Point (AP)**: ให้อุปกรณ์ไร้สายเข้าเครือข่าย
   - **Firewall**: คัดกรองว่าข้อมูลใดผ่านได้
3. **สื่อกลาง (Media)** — ทางที่ข้อมูลวิ่ง: สายทองแดง (UTP/LAN), ใยแก้วนำแสง (Fiber), คลื่นวิทยุ (Wi-Fi, 4G/5G)
4. **โพรโทคอล (Protocol)** — "ภาษาและกติกา" ที่ทุกอุปกรณ์ตกลงใช้ร่วมกัน เช่น Ethernet, IP, TCP, HTTP ถ้าไม่มีกติกาเดียวกัน อุปกรณ์จะคุยกันไม่รู้เรื่อง เหมือนคนพูดคนละภาษา

> 💡 **เปรียบเทียบ:** เครือข่ายคือ **ระบบไปรษณีย์**
> บ้านแต่ละหลัง = อุปกรณ์ปลายทาง · ที่ทำการไปรษณีย์ = switch/router · ถนน = สื่อกลาง · รูปแบบการจ่าหน้าซองและที่อยู่ = protocol

### ตัวอย่าง: เครือข่ายในบ้าน

```
             อินเทอร์เน็ต (ISP)
                   │ สายไฟเบอร์
              ┌────┴────┐
              │ ONT/Router│  ← กล่องจากผู้ให้บริการ: router + switch + Wi-Fi AP ในกล่องเดียว
              └┬───┬───┬─┘
        สาย LAN │   │   │ Wi-Fi
           ┌────┘   │   └────────┐
         [PC]   [Smart TV]   [มือถือ] [โน้ตบุ๊ก]
```

กล่องเดียวในบ้านจึงทำหน้าที่หลายอย่างพร้อมกัน ส่วนในองค์กร อุปกรณ์แต่ละหน้าที่จะแยกเป็นคนละเครื่อง เพื่อให้รองรับผู้ใช้ได้มากขึ้นและทนทานกว่า

## 2. ประเภทของเครือข่ายตามขนาด

ไล่จากเล็กไปใหญ่

```
PAN  →  LAN / WLAN  →  Campus (CAN)  →  MAN  →  WAN  →  Internet
ตัวคน     ห้อง/ชั้น/อาคาร     หลายอาคาร       ทั้งเมือง   ประเทศ/ทั่วโลก
```

### 2.1 PAN — Personal Area Network

- **ขนาด:** รอบตัวคน ประมาณ 1–10 เมตร
- **เทคโนโลยี:** Bluetooth, USB, NFC, Wi-Fi Direct, UWB
- **ตัวอย่าง:** มือถือต่อหูฟังไร้สาย, smartwatch ซิงก์กับมือถือ, แชร์เน็ตมือถือ (hotspot) ให้โน้ตบุ๊ก
- **จุดเด่น:** ใช้ส่วนตัว ตั้งค่าง่าย ไม่ต้องมีอุปกรณ์เครือข่ายกลาง

### 2.2 LAN — Local Area Network

- **ขนาด:** พื้นที่จำกัด เช่น บ้าน ห้องเรียน ชั้นสำนักงาน หรืออาคารเดียว
- **เจ้าของ:** องค์กรหรือเจ้าของบ้านเป็นเจ้าของและดูแลเอง
- **เทคโนโลยี:** Ethernet (สาย LAN), switch
- **ความเร็ว:** สูง 1 Gbps ถึง 10 Gbps ขึ้นไป ค่าหน่วงต่ำมาก (ต่ำกว่า 1 ms)
- **ตัวอย่าง:** คอมพิวเตอร์ทุกเครื่องในแผนกบัญชีต่อ switch เดียวกัน

### 2.3 WLAN — Wireless LAN

- คือ **LAN ที่ใช้คลื่นวิทยุแทนสาย** ก็คือ **Wi-Fi** (มาตรฐาน IEEE 802.11)
- ใช้ **Access Point** เป็นตัวเชื่อม
- **ข้อดี:** เคลื่อนที่ได้ ไม่ต้องเดินสาย
- **ข้อจำกัด:** ความเร็วจริงแปรผันตามระยะ สิ่งกีดขวาง และจำนวนผู้ใช้ เพราะทุกเครื่องแชร์คลื่นเดียวกัน และต้องดูแลความปลอดภัยมากกว่าใช้สาย
- **ตัวอย่าง:** Wi-Fi ในบ้าน ร้านกาแฟ สำนักงาน

### 2.4 Campus Network (CAN)

- **ขนาด:** **หลายอาคารในบริเวณเดียวกัน** เช่น มหาวิทยาลัย โรงพยาบาล โรงงาน สำนักงานใหญ่
- **เจ้าของ:** องค์กรเดียวเป็นเจ้าของทั้งหมด รวมถึงสายไฟเบอร์ที่เชื่อมระหว่างอาคาร
- **โครงสร้าง:** แบ่งเป็นลำดับชั้น Core – Distribution – Access (ดู Level 40)
- **ตัวอย่าง:** โรงพยาบาลที่มี 5 อาคาร ทุกอาคารต่อไฟเบอร์กลับไปห้อง server กลาง

### 2.5 MAN — Metropolitan Area Network

- **ขนาด:** ระดับ **เมือง** ระยะหลายสิบกิโลเมตร
- **เจ้าของ:** มักเป็นผู้ให้บริการ (ISP/Telco) หรือหน่วยงานรัฐที่ลากสายทั่วเมือง
- **เทคโนโลยี:** Metro Ethernet, fiber ring
- **ตัวอย่าง:** บริษัทเช่าวงจร Metro-E เชื่อมสำนักงาน 3 แห่งในกรุงเทพฯ, เครือข่ายกล้อง CCTV ทั้งเมือง

### 2.6 WAN — Wide Area Network

- **ขนาด:** ข้ามจังหวัด ข้ามประเทศ หรือทั่วโลก
- **เจ้าของ:** องค์กรไม่ได้เป็นเจ้าของสายเอง ต้อง **เช่าจากผู้ให้บริการ**
- **เทคโนโลยี:** MPLS, leased line, อินเทอร์เน็ต + VPN, SD-WAN, ดาวเทียม
- **ความเร็ว:** ต่ำกว่า LAN และค่าหน่วงสูงกว่า (ระยะไกล) แต่ราคาต่อ Mbps แพงกว่ามาก
- **ตัวอย่าง:** ธนาคารเชื่อมสำนักงานใหญ่กับสาขาทั่วประเทศ
- **อินเทอร์เน็ต** คือ WAN ที่ใหญ่ที่สุดในโลก

### 2.7 SAN — Storage Area Network

- ⚠️ SAN **ไม่ได้แบ่งตามขนาด** แต่แบ่งตาม **หน้าที่**: เป็นเครือข่ายเฉพาะสำหรับเชื่อม **server กับ storage (ที่เก็บข้อมูล)**
- server จะมองเห็นพื้นที่ใน storage เหมือนเป็นฮาร์ดดิสก์ของตัวเอง
- **เทคโนโลยี:** Fibre Channel (FC), iSCSI, NVMe over Fabrics
- **ตัวอย่าง:** ใน data center มี server 10 เครื่องใช้ storage กลางร่วมกันผ่าน SAN (ดู Level 25 ใน SI-Track)
- อย่าสับสนกับ **NAS** (Network Attached Storage) ซึ่งเป็นกล่องแชร์ไฟล์ผ่าน LAN ปกติ

### ตารางเปรียบเทียบ

| ประเภท | ขนาด/ระยะ | เจ้าของ | ความเร็ว | ตัวอย่าง |
|---|---|---|---|---|
| **PAN** | ~10 m | ส่วนตัว | ต่ำ–กลาง | หูฟัง Bluetooth |
| **LAN** | ห้อง–อาคาร | องค์กร | สูงมาก | switch ในสำนักงาน |
| **WLAN** | ห้อง–อาคาร | องค์กร | กลาง–สูง (แปรผัน) | Wi-Fi |
| **Campus** | หลายอาคาร | องค์กร | สูงมาก | มหาวิทยาลัย, โรงพยาบาล |
| **MAN** | ทั้งเมือง | ISP/หน่วยงาน | สูง | Metro-E เชื่อมสาขาในเมือง |
| **WAN** | ประเทศ/โลก | เช่า ISP | ต่ำกว่า LAN (แพงกว่า) | สำนักงานใหญ่ ↔ สาขา |
| **SAN** | ใน data center | องค์กร | สูงมาก | server ↔ storage |

> 💡 **จำง่าย:** ถ้าเป็นเจ้าของสายเองและอยู่ในพื้นที่เดียว ก็คือ **LAN/Campus** ถ้าต้องเช่าสายวิ่งไกล ก็คือ **WAN**

## 3. Topology — รูปแบบการเชื่อมต่อ

**Topology** คือ "แผนผัง" ว่าอุปกรณ์เชื่อมต่อกันเป็นรูปร่างอย่างไร Topology ที่เลือกมีผลต่อราคา ความเร็ว และ **ความทนทานเมื่อมีจุดเสีย**

### 3.1 Bus (แบบบัส)

```
 [PC1]     [PC2]     [PC3]     [PC4]
   │         │         │         │
 ■━┷━━━━━━━━━┷━━━━━━━━━┷━━━━━━━━━┷━■   ← สายหลักเส้นเดียว (backbone)
 Terminator                       Terminator
```

- **หลักการ:** ทุกเครื่องเกาะอยู่บน **สายหลักเส้นเดียว** ข้อมูลที่ส่งจะวิ่งไปทั้งเส้น ทุกเครื่องได้รับ แต่เครื่องที่ข้อมูลไม่ได้ส่งถึงจะไม่สนใจ
- ปลายสายทั้ง 2 ข้างต้องมี **terminator** ไม่เช่นนั้นสัญญาณจะสะท้อนกลับ
- ถ้าส่งพร้อมกันจะเกิด **การชน (collision)** ต้องใช้กลไก CSMA/CD ให้รอแล้วส่งใหม่
- ✅ **ข้อดี:** ใช้สายน้อย ราคาถูก ติดตั้งง่าย
- ❌ **ข้อเสีย:** สายหลักขาดจุดเดียว ทั้งเครือข่ายล่ม, เครื่องยิ่งมากยิ่งชนกันบ่อยและช้า, หาจุดเสียยาก
- 📍 **ปัจจุบัน:** แทบไม่ใช้แล้วใน LAN (เคยใช้กับสาย coaxial ยุคก่อน) แต่แนวคิด "สื่อกลางที่ทุกคนแชร์ร่วมกัน" ยังเห็นได้ใน Wi-Fi

### 3.2 Star (แบบดาว) ⭐ ใช้มากที่สุดในปัจจุบัน

```
           [PC1]   [PC2]
               \     /
     [PC6] ── [ SWITCH ] ── [PC3]
               /     \
           [PC5]   [PC4]
```

- **หลักการ:** ทุกเครื่องต่อสายของตัวเองเข้า **อุปกรณ์ศูนย์กลาง** (switch/AP)
- ✅ **ข้อดี:**
  - สายเส้นหนึ่งเสีย กระทบเฉพาะเครื่องนั้น
  - เพิ่ม/ถอดเครื่องง่าย
  - หาปัญหาง่าย (ดูไฟพอร์ตที่ switch)
  - switch ส่งข้อมูลเฉพาะเครื่องปลายทาง ไม่ชนกัน
- ❌ **ข้อเสีย:**
  - **ศูนย์กลางเสีย ทุกเครื่องหลุดหมด** (Single Point of Failure)
  - ใช้สายมากกว่า Bus
- 📍 **ปัจจุบัน:** LAN ในบ้านและสำนักงานแทบทั้งหมด รวมถึง Wi-Fi (ทุกเครื่องเชื่อม AP)
- 🔧 **แก้จุดอ่อน:** ในองค์กรจะใช้ switch ศูนย์กลาง 2 ตัวสำรองกัน

### 3.3 Ring (แบบวงแหวน)

```
        [PC1] ──── [PC2]
          │           │
        [PC4] ──── [PC3]
     ข้อมูลวิ่งวนตามทิศทาง →
```

- **หลักการ:** แต่ละเครื่องต่อกับเพื่อนบ้าน 2 ข้างจนครบวง ข้อมูลส่งต่อกันเป็นทอด ๆ
- แบบดั้งเดิมใช้ **Token Passing**: มี "โทเค็น" วนอยู่ในวง ใครถือโทเค็นจึงส่งได้ จึงไม่ชนกัน
- ✅ **ข้อดี:** ไม่มีการชน, ทุกเครื่องได้สิทธิ์ส่งเท่ากัน
- ❌ **ข้อเสีย:** วงเดี่ยวขาดจุดเดียวกระทบทั้งวง, เพิ่มเครื่องต้องตัดวง
- 🔧 **แก้ด้วย Dual Ring:** มี 2 วงวิ่งสวนทางกัน ถ้าวงหนึ่งขาด อีกวงพาข้อมูลอ้อมไปได้
- 📍 **ปัจจุบัน:** Token Ring ใน LAN เลิกใช้แล้ว แต่ **วงแหวนไฟเบอร์ (fiber ring)** ยังใช้มากในเครือข่ายผู้ให้บริการ เครือข่ายระดับเมือง (MAN) และ backbone ระหว่างอาคาร เพราะมีเส้นทางสำรองอ้อมอีกทาง

### 3.4 Mesh (แบบตาข่าย)

**Full Mesh — ทุกตัวต่อกับทุกตัว**

```
     [A]━━━━━━[B]
      ┃ ╲    ╱ ┃
      ┃   ╳    ┃
      ┃ ╱    ╲ ┃
     [D]━━━━━━[C]
```

- จำนวนสายที่ต้องใช้ = **n(n−1)/2** (n = จำนวนอุปกรณ์)
  - 4 ตัว → 4×3/2 = **6 เส้น**
  - 10 ตัว → 10×9/2 = **45 เส้น**
  - 50 ตัว → 50×49/2 = **1,225 เส้น** 😱
- ✅ **ข้อดี:** ทนทานที่สุด สายเส้นใดขาดก็มีทางอื่นเสมอ ส่งตรงถึงกันได้
- ❌ **ข้อเสีย:** สาย/พอร์ต/ค่าใช้จ่ายโตเร็วมากตามจำนวนอุปกรณ์ จัดการยาก

**Partial Mesh — ต่อบางคู่ที่สำคัญ**

```
     [A]━━━━━━[B]
      ┃        ┃
      ┃        ┃
     [D]━━━━━━[C]━━━━[E]
```

- เลือกต่อสำรองเฉพาะจุดสำคัญ ได้ความทนทานในราคาที่รับได้
- 📍 **ปัจจุบัน:** WAN ขององค์กร (สาขาหลักต่อหลายเส้น), core router ของ ISP, **อินเทอร์เน็ตโดยรวมก็เป็น partial mesh**, ระบบ **Mesh Wi-Fi** ในบ้าน

### 3.5 Hybrid (แบบผสม)

```
                 [Core Switch]                 ← ชั้นบน
                /      |       \
        [Switch A] [Switch B] [Switch C]       ← แต่ละชั้น/อาคาร
         /  |  \     /  |  \     /  |  \
       PC  PC  PC  PC  PC  PC  PC  PC  PC      ← แต่ละกลุ่มเป็น Star
```

- **หลักการ:** เอาหลาย topology มารวมกัน เช่น หลาย Star มาต่อกันเป็นลำดับชั้น (เรียก **Tree** หรือ Hierarchical/Extended Star) หรือ Star ภายในอาคาร + Ring ระหว่างอาคาร
- ✅ **ข้อดี:** เลือกข้อดีของแต่ละแบบมาใช้ในแต่ละจุด ขยายง่าย
- ❌ **ข้อเสีย:** ออกแบบและดูแลซับซ้อนกว่า
- 📍 **ปัจจุบัน:** **เครือข่ายองค์กรจริงเกือบทั้งหมดเป็น Hybrid** เช่น Campus แบบ Core–Distribution–Access

### 3.6 Spine-Leaf (Data Center สมัยใหม่)

```
         [Spine 1]           [Spine 2]          ← ชั้นบน: เชื่อมทุก leaf
          │ │ │ ╲            ╱ │ │ │
          │ │ │   ╲        ╱   │ │ │
          │ │ │     ╲    ╱     │ │ │            (ทุก Leaf ต่อกับทุก Spine)
          │ │ │      ╱ ╲       │ │ │
       [Leaf 1]   [Leaf 2]   [Leaf 3]           ← ชั้นล่าง: switch บนหัวตู้ (ToR)
        │   │      │   │      │   │
       Server     Server     Server
```

- **ที่มา:** ใน data center ยุคใหม่ server คุยกันเอง (**East-West traffic**) มากกว่าคุยออกนอก (North-South) เช่น app ↔ database ↔ storage ↔ VM ย้ายเครื่อง โครงสร้าง 3 ชั้นแบบเดิมจึงกลายเป็นคอขวด
- **กติกา 2 ข้อ:**
  1. **Leaf ทุกตัวต่อกับ Spine ทุกตัว**
  2. Spine ไม่ต่อกันเอง Leaf ไม่ต่อกันเอง
- **ผลลัพธ์:**
  - server 2 เครื่องที่อยู่คนละ leaf ห่างกันแค่ **Leaf → Spine → Leaf** เสมอ ทุกคู่เท่ากัน จึงคาดเดาค่าหน่วงได้
  - ใช้ทุกเส้นทางพร้อมกัน (ECMP) ไม่มีเส้นไหนถูกบล็อกทิ้ง
  - Spine ตัวหนึ่งเสีย ยังมีตัวอื่นรับงาน
  - **ขยายง่าย:** ต้องการพอร์ตเพิ่มก็เพิ่ม Leaf ต้องการ bandwidth เพิ่มก็เพิ่ม Spine
- 📍 **ปัจจุบัน:** มาตรฐานของ data center, cloud และ AI/GPU cluster (ดู Level 73)

### ตารางเปรียบเทียบ Topology

| Topology | ทนจุดเสีย | ราคา/สาย | ขยาย | หาปัญหา | ใช้จริงวันนี้ |
|---|---|---|---|---|---|
| Bus | ❌ ต่ำมาก | ถูกที่สุด | ยาก | ยาก | แทบไม่ใช้ |
| Star | ⚠️ ศูนย์กลางเป็นจุดอ่อน | ปานกลาง | ง่าย | ง่าย | ✅ LAN ทั่วไป, Wi-Fi |
| Ring | ⚠️ ดีขึ้นมากถ้าเป็น Dual Ring | ปานกลาง | ยาก | ปานกลาง | ✅ Fiber ring ของ ISP/MAN |
| Full Mesh | ✅ สูงสุด | แพงที่สุด | ยากมาก | ซับซ้อน | core เล็ก ๆ ที่สำคัญมาก |
| Partial Mesh | ✅ สูง | ปานกลาง–สูง | ปานกลาง | ซับซ้อน | ✅ WAN, อินเทอร์เน็ต |
| Hybrid/Tree | ✅ ตามการออกแบบ | ตามการออกแบบ | ง่าย | ปานกลาง | ✅ องค์กรเกือบทั้งหมด |
| Spine-Leaf | ✅ สูง | สูง | ง่ายมาก | ง่าย (โครงสร้างสม่ำเสมอ) | ✅ Data Center/Cloud |

## 4. Physical Topology ≠ Logical Topology

| | ความหมาย | ถามว่า |
|---|---|---|
| **Physical Topology** | การเดินสายและวางอุปกรณ์จริง ๆ | "สายต่อจากไหนไปไหน" |
| **Logical Topology** | ข้อมูลไหลจริงอย่างไร ใครคุยกับใครได้ | "ข้อมูลวิ่งยังไง" |

สองอย่างนี้ **ไม่จำเป็นต้องเหมือนกัน** ตัวอย่างที่เห็นชัดที่สุด

### ตัวอย่าง 1: Hub — ดูเหมือน Star แต่ทำงานเหมือน Bus

```
 Physical (มองด้วยตา)         Logical (ข้อมูลวิ่งจริง)
      [PC1]                    PC1  PC2  PC3  PC4
        │                       │    │    │    │
 [PC4]─[HUB]─[PC2]           ━━━┷━━━━┷━━━━┷━━━━┷━━━
        │                    ทุกเครื่องได้รับทุกข้อมูล
      [PC3]                  และชนกันได้เหมือนสายเส้นเดียว
```

**Hub** เป็นอุปกรณ์รุ่นเก่า ทุกเครื่องเสียบสายเข้า hub เหมือน switch (Physical = Star) แต่ hub **กระจายข้อมูลออกทุกพอร์ต** ทำให้ทำงานเหมือนสายเส้นเดียวที่ทุกคนแชร์ (Logical = Bus) ส่วน **switch** จะส่งไปเฉพาะเครื่องปลายทาง จึงเป็น Star ทั้งทางกายภาพและทางตรรกะ

### ตัวอย่าง 2: VLAN — switch ตัวเดียว แต่แยกเป็นหลายเครือข่าย

```
 Physical: ทุกเครื่องเสียบ switch ตัวเดียวกัน
 ┌──────────────── SWITCH ────────────────┐
 │ พอร์ต 1-12 = VLAN 10  │ พอร์ต 13-24 = VLAN 20 │
 └────────────────────────────────────────┘
     บัญชี (คุยกันได้)          HR (คุยกันได้)

 Logical: กลายเป็น 2 เครือข่ายแยกกัน บัญชีคุยกับ HR ตรง ๆ ไม่ได้
```

### ตัวอย่าง 3: Token Ring
เดินสายเป็น Star เข้ากล่องกลาง (MAU) แต่ภายในกล่องต่อวงจรให้ข้อมูลวิ่งวน จึงเป็น Physical = Star แต่ Logical = Ring

### ตัวอย่าง 4: VPN
บริษัทกับบ้านพนักงานเชื่อมผ่านอินเทอร์เน็ต (physical ผ่าน router นับสิบ hop) แต่ในมุม logical เหมือนเครื่องที่บ้านต่อสายตรงเข้าสำนักงาน

> 🔑 **ทำไมต้องรู้เรื่องนี้ในการทำงาน:**
> เวลาแก้ปัญหา ต้องดูทั้ง 2 มุม เช่น สองเครื่องเสียบ switch ตัวเดียวกันแต่ ping กันไม่ได้ อาจเพราะอยู่คนละ VLAN (ปัญหาเชิง logical) ไม่ใช่สายเสีย (ปัญหาเชิง physical)
> เอกสารเครือข่ายที่ดีจึงต้องมีทั้ง **Physical diagram** (สาย พอร์ต ตู้ rack) และ **Logical diagram** (VLAN, IP, routing)

## 5. Client-Server vs Peer-to-Peer

เรื่องนี้ไม่ได้ดูที่สาย แต่ดูที่ **"บทบาท" ของแต่ละเครื่อง** ว่าใครให้บริการ ใครขอใช้

### 5.1 Client-Server

```
   [Client]  [Client]  [Client]
       \        |        /
        \  ขอ (Request) /
         ▼      ▼      ▼
         ┌──────────────┐
         │   SERVER     │  ← ให้บริการ (Response)
         └──────────────┘
```

- **Server** = เครื่องที่ **ให้บริการ** เปิดรอรับคำขอตลอดเวลา มักเป็นเครื่องแรง ทำงาน 24 ชม.
- **Client** = เครื่องที่ **ขอใช้บริการ**
- **ตัวอย่าง:**
  - เปิดเว็บ: browser (client) ขอหน้าเว็บจาก web server
  - อีเมล: Outlook (client) ↔ mail server (Exchange/Gmail)
  - ไฟล์กลางของบริษัท: เครื่องพนักงาน ↔ file server
  - login เข้าคอมพิวเตอร์บริษัท: เครื่องพนักงาน ↔ Active Directory server
  - เกมออนไลน์, แอปธนาคาร, LINE (ส่วนใหญ่วิ่งผ่าน server)
- ✅ **ข้อดี:** จัดการจากศูนย์กลาง (สิทธิ์ ความปลอดภัย backup ทำที่เดียว), ขยายรองรับผู้ใช้จำนวนมากได้, ข้อมูลไม่กระจัดกระจาย
- ❌ **ข้อเสีย:** server ราคาแพงและต้องมีคนดูแล, **server ล่มทุกคนใช้งานไม่ได้** (จึงต้องทำ HA/สำรอง)

### 5.2 Peer-to-Peer (P2P)

```
   [Peer A] ◄──────► [Peer B]
      ▲   ╲         ╱   ▲
      │     ╲     ╱     │
      ▼       ╲ ╱       ▼
   [Peer D] ◄──────► [Peer C]
   ทุกเครื่องเป็นทั้งผู้ให้และผู้ขอ
```

- ทุกเครื่อง **เท่าเทียมกัน** เป็นทั้ง client และ server ในเวลาเดียวกัน ไม่มีเครื่องศูนย์กลาง
- **ตัวอย่าง:**
  - แชร์โฟลเดอร์/เครื่องพิมพ์ระหว่างคอม 3–5 เครื่องในบ้าน (Windows Workgroup)
  - AirDrop, Nearby Share
  - BitTorrent: โหลดไฟล์จากหลายคนพร้อมกัน และส่งต่อให้คนอื่นด้วย
  - Blockchain
- ✅ **ข้อดี:** ถูก ไม่ต้องมี server, ตั้งง่ายสำหรับกลุ่มเล็ก, ไม่มีจุดศูนย์กลางให้ล่ม
- ❌ **ข้อเสีย:** จัดการยากเมื่อมีหลายเครื่อง (ต้องตั้งสิทธิ์ทีละเครื่อง), ความปลอดภัยต่ำ, ข้อมูลกระจายอยู่หลายที่ backup ยาก, ถ้าเครื่องที่แชร์ไฟล์ปิดก็เข้าไฟล์ไม่ได้

### ตารางเปรียบเทียบ

| หัวข้อ | Client-Server | Peer-to-Peer |
|---|---|---|
| ศูนย์กลาง | มี (server) | ไม่มี |
| บทบาท | แยกชัด ผู้ให้/ผู้ขอ | ทุกเครื่องเป็นทั้งสองอย่าง |
| ขนาดที่เหมาะ | ตั้งแต่ 10 คนขึ้นไปจนถึงล้านคน | ไม่เกิน ~10 เครื่อง (หรือแอป P2P เฉพาะทาง) |
| ความปลอดภัย/จัดการ | ดี ทำที่เดียว | ยาก ต้องทำทีละเครื่อง |
| ค่าใช้จ่าย | สูง (server + คนดูแล) | ต่ำ |
| จุดอ่อน | server ล่ม = ล่มทั้งหมด | ไม่มีมาตรฐานกลาง, ควบคุมยาก |
| ตัวอย่าง | เว็บ, อีเมล, ERP, Active Directory | แชร์ไฟล์ในบ้าน, BitTorrent, AirDrop |

> 💡 **แบบผสม (Hybrid):** หลายระบบใช้ server ช่วยให้สองฝั่งหากันเจอ แล้วค่อยส่งข้อมูลหากันตรง ๆ เช่น วิดีโอคอลบางแอปที่ส่งภาพตรงระหว่างผู้ใช้เมื่อทำได้
>
> 🏢 **ในองค์กร:** แทบทั้งหมดเป็น **Client-Server** เพราะต้องควบคุมสิทธิ์ ความปลอดภัย และ backup ได้

## 6. หน่วยวัดและคุณภาพของเครือข่าย

### 6.1 bit vs Byte — ต้องแยกให้ขาด

| หน่วย | ตัวย่อ | ความหมาย |
|---|---|---|
| **bit** | **b** (ตัวเล็ก) | หน่วยเล็กที่สุด มีค่า 0 หรือ 1 |
| **Byte** | **B** (ตัวใหญ่) | **1 Byte = 8 bit** (เก็บตัวอักษรภาษาอังกฤษได้ 1 ตัว) |

**กฎที่ต้องจำ:**
- 🌐 **ความเร็วเครือข่าย** ใช้ **bit ต่อวินาที (bps)** เช่น เน็ต 1 Gbps, Wi-Fi 600 Mbps
- 💾 **ขนาดไฟล์ / ความจุ** ใช้ **Byte** เช่น ไฟล์ 5 GB, ฮาร์ดดิสก์ 1 TB
- 📥 **ความเร็วดาวน์โหลดในโปรแกรม** มักแสดงเป็น **Byte ต่อวินาที** เช่น 50 MB/s

**แปลงหน่วย:** Byte → bit **คูณ 8** · bit → Byte **หาร 8**

```
 Mbps  ──÷ 8──►  MB/s
 MB/s  ──×8──►  Mbps
```

### 6.2 คำนำหน้า (Prefix)

| หน่วยความเร็ว | เท่ากับ | อ่านว่า |
|---|---|---|
| **bps** | 1 bit ต่อวินาที | บิตต่อวินาที |
| **Kbps** | 1,000 bps | กิโลบิต |
| **Mbps** | 1,000,000 bps (10⁶) | เมกะบิต |
| **Gbps** | 1,000,000,000 bps (10⁹) | กิกะบิต |
| **Tbps** | 10¹² bps | เทราบิต |

> ⚠️ **ความเร็วเครือข่ายใช้ฐาน 1,000 เสมอ** (1 Gbps = 1,000 Mbps)
> ส่วนความจุในระบบปฏิบัติการบางครั้งใช้ฐาน 1,024 และเขียนเป็น KiB/MiB/GiB เช่น Windows แสดง "GB" แต่จริง ๆ คำนวณแบบ 1,024 นี่คือเหตุผลที่ฮาร์ดดิสก์ 1 TB เสียบแล้วเห็นแค่ประมาณ 931 GB

### 6.3 ตัวอย่างคำนวณที่เจอบ่อย

**ตัวอย่าง 1: เน็ตบ้าน 1 Gbps โหลดได้กี่ MB/s**
```
1 Gbps = 1,000 Mbps ÷ 8 = 125 MB/s (ทางทฤษฎี)
ของจริง ≈ 110–118 MB/s (หัก overhead ของ header/protocol)
```

**ตัวอย่าง 2: ดาวน์โหลดเกม 50 GB ด้วยเน็ต 500 Mbps ใช้เวลาเท่าไร**
```
50 GB = 50 × 8 = 400 Gb = 400,000 Mb
เวลา = 400,000 ÷ 500 = 800 วินาที ≈ 13.3 นาที (ขั้นต่ำทางทฤษฎี)
```

**ตัวอย่าง 3: โปรแกรมโหลดแสดง 12.5 MB/s เน็ตเร็วเท่าไร**
```
12.5 × 8 = 100 Mbps
```

**ตัวอย่าง 4: แบ็กอัปข้อมูล 2 TB ข้ามสาขาด้วยลิงก์ 100 Mbps ใช้เวลาเท่าไร**
```
2 TB = 2,000,000 MB × 8 = 16,000,000 Mb
เวลา = 16,000,000 ÷ 100 = 160,000 วินาที ≈ 44 ชั่วโมง ≈ 1.85 วัน
→ ในงานจริงต้องวางแผน: ใช้ลิงก์เร็วขึ้น, ส่งเฉพาะส่วนที่เปลี่ยน (incremental), หรือขนดิสก์ไปเอง
```

### 6.4 Bandwidth vs Throughput vs Latency vs Jitter

ใช้ **"ถนน"** เป็นตัวเปรียบเทียบ

```
 ═══════════════════════════════════════════   ← ความกว้างถนน (จำนวนเลน) = BANDWIDTH
   🚗 🚗    🚗   🚗🚗      🚗                   ← รถที่วิ่งผ่านได้จริงต่อชั่วโมง = THROUGHPUT
 ต้นทาง ───────── เวลาเดินทาง ─────────► ปลายทาง  ← = LATENCY
                 เวลาเดินทางแต่ละคันไม่เท่ากัน     ← = JITTER
```

#### 🛣️ Bandwidth — ความจุสูงสุด

- **ความหมาย:** ปริมาณข้อมูล **สูงสุดตามทฤษฎี** ที่ลิงก์รองรับได้ต่อวินาที
- **หน่วย:** bps (Mbps, Gbps)
- **เปรียบ:** ความกว้างของถนน (จำนวนเลน)
- **ตัวอย่าง:** แพ็กเกจเน็ต 1 Gbps, พอร์ต switch 10 Gbps
- ⚠️ เป็น "เพดาน" ไม่ใช่ความเร็วที่ได้จริง

#### 🚗 Throughput — ที่ได้จริง

- **ความหมาย:** ปริมาณข้อมูลที่ **ส่งได้จริง** ต่อวินาที ณ ช่วงเวลานั้น
- **หน่วย:** bps
- **เปรียบ:** จำนวนรถที่วิ่งผ่านได้จริง ซึ่งน้อยกว่าความจุถนนเสมอ เพราะมีรถติด สัญญาณไฟ อุบัติเหตุ
- **ทำไมได้น้อยกว่า Bandwidth:**
  - overhead ของ protocol (header ต่าง ๆ)
  - มีคนใช้ร่วม (congestion)
  - packet หาย ต้องส่งซ้ำ
  - ค่าหน่วงสูงทำให้ TCP ส่งได้ช้าลง
  - Wi-Fi สัญญาณอ่อน/คลื่นรบกวน
  - อุปกรณ์ปลายทางช้า (ดิสก์, CPU, server)
  - **จุดที่ช้าที่สุดในเส้นทาง** (คอขวด) เป็นตัวกำหนด
- **วัดด้วย:** speedtest, iperf3
- 📝 คำที่ใกล้กัน: **Goodput** = ข้อมูลที่เป็นประโยชน์จริงที่แอปได้รับ (หัก header และการส่งซ้ำออกแล้ว)

#### ⏱️ Latency — ความหน่วง

- **ความหมาย:** **เวลา** ที่ข้อมูลใช้เดินทางจากต้นทางถึงปลายทาง
- **หน่วย:** มิลลิวินาที (**ms**)
- **เปรียบ:** เวลาที่รถหนึ่งคันใช้เดินทาง (ไม่เกี่ยวกับว่าถนนกว้างแค่ไหน)
- **RTT (Round-Trip Time):** เวลาไป-กลับ คือค่าที่เห็นจากคำสั่ง `ping`
- **ความหน่วงเกิดจาก 4 ส่วน:**
  1. **Propagation delay** — ระยะทาง: แสงในไฟเบอร์วิ่งประมาณ 200,000 km/s หรือ **ประมาณ 5 µs ต่อ 1 km** ไกลแค่ไหนก็หลีกเลี่ยงไม่ได้
  2. **Transmission (Serialization) delay** — เวลาปล่อยข้อมูลลงสาย: ลิงก์ช้าใช้เวลานานกว่า
  3. **Queuing delay** — รอคิวในอุปกรณ์เมื่อมีข้อมูลแน่น (ตัวแปรหลักตอนเน็ตช้า)
  4. **Processing delay** — เวลาที่ router/firewall ใช้ตรวจและส่งต่อ
- **ตัวอย่างค่าจริงโดยประมาณ:**

| ปลายทาง | RTT โดยประมาณ |
|---|---|
| ภายใน LAN เดียวกัน | < 1 ms |
| Wi-Fi ในบ้าน → router | 1–10 ms |
| กรุงเทพฯ → server ในไทย | 5–20 ms |
| กรุงเทพฯ → สิงคโปร์ | 25–40 ms |
| กรุงเทพฯ → ญี่ปุ่น | 50–80 ms |
| กรุงเทพฯ → สหรัฐฯ | 180–250 ms |
| อินเทอร์เน็ตดาวเทียมวงโคจรค้างฟ้า (GEO) | 600 ms ขึ้นไป |

- **งานที่ไวต่อ latency:** เกมออนไลน์, วิดีโอคอล, VoIP, ระบบซื้อขายหุ้น, remote desktop

#### 📉 Jitter — ความไม่สม่ำเสมอของความหน่วง

- **ความหมาย:** **ความแปรปรวน** ของ latency ระหว่าง packet แต่ละตัว
- **หน่วย:** ms
- **เปรียบ:** รถออกจากต้นทางทุก 1 นาทีเท่า ๆ กัน แต่ถึงปลายทางห่างกันไม่เท่ากัน บางคันมาติดกัน บางคันทิ้งช่วงนาน
- **ตัวอย่าง:**
  ```
  ping ครั้งที่ 1 = 20 ms
  ping ครั้งที่ 2 = 22 ms
  ping ครั้งที่ 3 = 80 ms   ← กระโดด
  ping ครั้งที่ 4 = 21 ms
  → Latency เฉลี่ยไม่สูงมาก แต่ Jitter สูง
  ```
- **ผลกระทบ:** เสียงในการโทรขาด ๆ หาย ๆ หรือเสียงหุ่นยนต์, วิดีโอกระตุก, เกม "วาร์ป"
- **สาเหตุ:** เครือข่ายแน่นเป็นช่วง ๆ, Wi-Fi ถูกรบกวน, ไม่มี QoS จัดลำดับความสำคัญ
- **แก้:** ใช้สายแทน Wi-Fi, ทำ QoS ให้เสียง/วิดีโอได้สิทธิ์ก่อน, ลดการใช้งานหนักช่วงเดียวกัน, ใช้ jitter buffer ในแอป

#### 📦 (แถม) Packet Loss — ข้อมูลหาย

- **ความหมาย:** % ของ packet ที่ส่งไปแล้วไม่ถึงปลายทาง
- ทำให้ TCP ต้องส่งซ้ำและลดความเร็วลง (throughput ตก) ส่วนเสียงหรือวิดีโอที่ใช้ UDP จะกระตุกหรือขาดหาย

### 6.5 สรุป 4 ค่า + เกณฑ์สำหรับงานเสียง/วิดีโอ

| ค่า | วัดอะไร | หน่วย | ดีเมื่อ | เครื่องมือวัด |
|---|---|---|---|---|
| **Bandwidth** | ความจุสูงสุด | Mbps/Gbps | ตามที่ซื้อ/สเปก | ดูสเปก/สัญญา |
| **Throughput** | ความเร็วที่ได้จริง | Mbps/Gbps | ใกล้ bandwidth | speedtest, iperf3 |
| **Latency** | เวลาเดินทาง | ms | ต่ำ | ping, traceroute |
| **Jitter** | ความแกว่งของเวลา | ms | ต่ำ | ping หลายครั้ง, mtr, speedtest |
| **Packet loss** | ข้อมูลหาย | % | ~0% | ping, mtr |

**เกณฑ์ที่นิยมใช้สำหรับ VoIP / วิดีโอคอล:** Latency (ทางเดียว) **< 150 ms** · Jitter **< 30 ms** · Packet loss **< 1%**

### 6.6 ความสัมพันธ์ที่ต้องเข้าใจ

> 🔑 **Bandwidth มาก ≠ Latency ต่ำ**

- ถนน 10 เลน กับถนน 2 เลน ถ้าระยะทาง กรุงเทพฯ → เชียงใหม่ เท่ากัน รถคันเดียวก็ใช้เวลาเดินทางพอ ๆ กัน
- เพิ่มแพ็กเกจเน็ตจาก 500 Mbps เป็น 1 Gbps **ไม่ทำให้ ping ไปเซิร์ฟเวอร์เกมที่อเมริกาลดลง** เพราะระยะทางยังเท่าเดิม
- **ไฟล์ใหญ่** (ดาวน์โหลด/backup) → สนใจ **Bandwidth/Throughput**
- **งาน real-time** (เกม/โทร/remote desktop) → สนใจ **Latency/Jitter** มากกว่า

> 🔑 **Latency สูงทำให้ Throughput ของการเชื่อมต่อเดียวลดลงได้**

TCP ต้องรอการตอบรับ (ACK) จากปลายทาง ยิ่งไกลยิ่งรอนาน การเชื่อมต่อเดียวไปต่างประเทศจึงอาจโหลดได้ไม่เต็มสาย แม้ bandwidth จะเหลือ (รายละเอียดดูเรื่อง TCP Window ใน Level 13)

|---|---|
| เน็ต 100 Mbps ดาวน์โหลดได้ 100 MB/s | ได้ประมาณ **12.5 MB/s** (หาร 8) |
| Wi-Fi บอก 1,200 Mbps ก็ต้องได้ 1,200 Mbps | นั่นคือ link rate สูงสุดทางทฤษฎี ใช้จริงมักได้ครึ่งหนึ่งหรือน้อยกว่า และแชร์กับทุกคนในคลื่นเดียวกัน |
| ซื้อเน็ตแรงขึ้นแล้ว ping เกมจะลด | ping ขึ้นกับระยะทางและเส้นทาง ไม่ใช่ขนาดท่อ |
| Router กับ Switch เหมือนกัน | Switch เชื่อมเครื่องในเครือข่ายเดียวกัน Router เชื่อมระหว่างเครือข่าย (กล่องที่บ้านมีทั้งสองอย่างในตัว) |
| Topology Star แปลว่าไม่มีจุดเสียเลย | ศูนย์กลางคือจุดเสียจุดเดียว ต้องทำสำรองในองค์กร |
| เสียบ switch ตัวเดียวกันต้องคุยกันได้แน่ | ถ้าอยู่คนละ VLAN ก็คุยกันไม่ได้ (logical ≠ physical) |
| SAN กับ NAS คือสิ่งเดียวกัน | SAN ให้พื้นที่แบบดิสก์ (block) ผ่านเครือข่ายเฉพาะ; NAS แชร์เป็นไฟล์ผ่าน LAN ปกติ |
| ความเร็วที่ speedtest วัดได้ = ความเร็วที่ทุกเว็บจะได้ | speedtest วัดไปเซิร์ฟเวอร์ใกล้ ๆ เท่านั้น เว็บต่างประเทศหรือ server ปลายทางที่ช้าจะได้น้อยกว่า |

## 8. สรุปท้ายบท (Cheat Sheet)

```
NETWORK      = อุปกรณ์ ≥ 2 ตัว เชื่อมกันเพื่อแชร์ข้อมูล/ทรัพยากร
องค์ประกอบ    = อุปกรณ์ปลายทาง + อุปกรณ์เครือข่าย + สื่อกลาง + Protocol

ขนาด         PAN < LAN/WLAN < Campus < MAN < WAN (Internet)
              SAN = เครือข่ายเฉพาะ server↔storage (แบ่งตามหน้าที่ ไม่ใช่ขนาด)
              เป็นเจ้าของสายเอง → LAN/Campus | เช่าสายวิ่งไกล → WAN

TOPOLOGY     Bus   = สายเส้นเดียว (เลิกใช้)
              Star  = ทุกเครื่องเข้าศูนย์กลาง (ใช้มากที่สุด, ศูนย์กลาง = จุดอ่อน)
              Ring  = วงแหวน (fiber ring ของ ISP)
              Mesh  = Full: n(n-1)/2 เส้น ทนสุดแพงสุด | Partial: เฉพาะจุดสำคัญ
              Hybrid= ผสม (องค์กรจริง)
              Spine-Leaf = ทุก Leaf ต่อทุก Spine, 2 hop เท่ากันทุกคู่ (Data Center)

PHYSICAL     = สายต่ออย่างไร   |   LOGICAL = ข้อมูลไหลอย่างไร
              Hub: Physical Star / Logical Bus   ·   VLAN: switch เดียว หลายเครือข่าย

CLIENT-SERVER= มีศูนย์กลาง จัดการง่าย ปลอดภัย (องค์กร)
P2P          = เท่าเทียมกัน ถูก ง่าย แต่จัดการ/ปลอดภัยยาก (กลุ่มเล็ก)

UNITS        b = bit, B = Byte, 1 B = 8 b
              ความเร็วเครือข่าย = bps (ฐาน 1,000) | ขนาดไฟล์ = Byte
              Mbps ÷ 8 = MB/s

QUALITY      Bandwidth  = ความจุสูงสุด (ความกว้างถนน)
              Throughput = ได้จริง (รถที่วิ่งผ่านจริง) ≤ Bandwidth
              Latency    = เวลาเดินทาง (ms), ping = RTT
              Jitter     = ความแกว่งของ latency (ms)
              VoIP ดีเมื่อ: latency < 150 ms, jitter < 30 ms, loss < 1%
              Bandwidth มาก ≠ Latency ต่ำ
```

7. PC 2 เครื่องเสียบ switch ตัวเดียวกัน ไฟพอร์ตติดปกติ แต่ ping กันไม่ได้ สาเหตุหนึ่งที่เป็นไปได้คืออะไร และเกี่ยวกับเรื่องใดในบทนี้
8. ออฟฟิศ 200 คนควรใช้ Client-Server หรือ Peer-to-Peer เพราะอะไร

10. ผู้ใช้บอกว่า "เน็ตแรง speedtest ได้ 900 Mbps แต่ประชุม Zoom เสียงขาด ๆ หาย ๆ" ควรตรวจค่าอะไร เพราะอะไร
