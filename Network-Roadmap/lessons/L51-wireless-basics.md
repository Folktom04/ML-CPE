## 1. Wi-Fi ต่างจาก LAN สายอย่างไร

| | Ethernet (สาย) | Wi-Fi (802.11) |
|---|---|---|
| สื่อกลาง | แต่ละเครื่องมีสายของตัวเอง | **อากาศ — ทุกเครื่องในคลื่นเดียวกันแชร์กัน** |
| Duplex | Full-duplex | **Half-duplex** (ส่งหรือรับทีละอย่าง, ทีละเครื่อง) |
| การเข้าถึงสื่อ | switch จัดการ ไม่ชน | **CSMA/CA** — ฟังก่อนส่ง รอสุ่ม ป้องกันการชน |
| ความเร็ว | คงที่ | **แปรผัน** ตามระยะ สิ่งกีดขวาง สัญญาณรบกวน จำนวนผู้ใช้ |
| ความปลอดภัย | ต้องเสียบสายในอาคาร | สัญญาณออกนอกอาคารได้ ต้องเข้ารหัสเสมอ |
| มาตรฐาน | IEEE 802.3 | **IEEE 802.11** (Wi-Fi Alliance รับรอง/ตั้งชื่อทางการตลาด) |

> 💡 **เปรียบเทียบ:** Wi-Fi คือ **ห้องประชุมที่ทุกคนใช้ไมค์ตัวเดียวกัน** — พูดได้ทีละคน ต้องฟังก่อนว่าว่างไหม คนยิ่งเยอะยิ่งรอนาน ส่วนคนที่อยู่ไกล (สัญญาณอ่อน) พูดช้าและกินเวลาของทุกคน

## 2. มาตรฐาน Wi-Fi

| ชื่อทางการตลาด | มาตรฐาน | ปี | คลื่น | Channel width สูงสุด | ความเร็วสูงสุดทางทฤษฎี | เทคโนโลยีเด่น |
|---|---|---|---|---|---|---|
| (Wi-Fi 1-3) | 802.11b/a/g | 1999–2003 | 2.4 / 5 | 20 MHz | 11–54 Mbps | — |
| **Wi-Fi 4** | 802.11n | 2009 | 2.4 / 5 | 40 MHz | 600 Mbps | MIMO |
| **Wi-Fi 5** | 802.11ac | 2013 | 5 | 160 MHz | ~3.5–6.9 Gbps | MU-MIMO (downlink), 256-QAM |
| **Wi-Fi 6** | 802.11ax | 2019 | 2.4 / 5 | 160 MHz | ~9.6 Gbps | **OFDMA**, MU-MIMO ขึ้น/ลง, **BSS Coloring**, **TWT**, 1024-QAM |
| **Wi-Fi 6E** | 802.11ax | 2021 | **+6 GHz** | 160 MHz | ~9.6 Gbps | คลื่น 6 GHz ที่ว่างกว่ามาก |
| **Wi-Fi 7** | 802.11be | 2024 | 2.4 / 5 / 6 | **320 MHz** | ~46 Gbps | **MLO (Multi-Link Operation)**, 4096-QAM |

> ⚠️ ความเร็วสูงสุดทางทฤษฎีคือผลรวมของทุก stream ในสภาพสมบูรณ์แบบ อุปกรณ์จริงหนึ่งเครื่อง (มือถือ 2 stream) ได้น้อยกว่ามาก (ดูข้อ 7)

**เทคโนโลยีสำคัญ**
- **MIMO / Spatial streams:** ใช้หลายเสาอากาศส่งหลายกระแสข้อมูลพร้อมกัน (2×2, 4×4)
- **MU-MIMO:** AP ส่งให้หลายเครื่องพร้อมกันด้วย stream ต่างกัน
- **OFDMA (Wi-Fi 6):** แบ่ง channel เป็นช่องย่อย (Resource Unit) ส่งให้หลายเครื่องในครั้งเดียว — ลด latency เมื่อมีอุปกรณ์จำนวนมากที่ส่งข้อมูลเล็ก ๆ
- **BSS Coloring:** แยกสัญญาณของ AP ตัวเองกับ AP ข้างเคียงที่ใช้ channel เดียวกัน ลดการรอโดยไม่จำเป็น
- **TWT (Target Wake Time):** ให้อุปกรณ์ IoT นัดเวลาตื่น ประหยัดแบตเตอรี่
- **MLO (Wi-Fi 7):** เชื่อมต่อหลายคลื่นพร้อมกัน (เช่น 5 + 6 GHz) เพิ่ม throughput และลด latency/ความเสี่ยงสัญญาณตก

## 3. คลื่นความถี่และ Channel

### 2.4 GHz
- ✅ ไปไกล ทะลุผนังได้ดี อุปกรณ์รองรับทุกตัว
- ❌ ช่องน้อย มีแค่ **3 channel ที่ไม่ทับกัน: 1, 6, 11** · แออัดมาก (เพื่อนบ้าน, Bluetooth, เตาไมโครเวฟ, IoT) · ช้า
- ใช้ channel width **20 MHz เท่านั้น** ในองค์กร

```
 2.4 GHz:  Ch1      Ch6      Ch11
          [====]   [====]   [====]      ← 3 ช่องไม่ทับกัน
            [====]  ช่อง 3 ทับกับ 1 และ 6 → ห้ามใช้
```

### 5 GHz
- ✅ มีหลายช่อง (ประมาณ 20+ ช่อง 20 MHz ขึ้นกับประเทศ) แออัดน้อยกว่า เร็วกว่า
- ❌ ระยะสั้นกว่า ทะลุผนังได้น้อยกว่า
- **DFS (Dynamic Frequency Selection):** บางช่องใช้ร่วมกับ **เรดาร์** (อากาศ/สนามบิน/ทหาร) AP ต้องตรวจและ **ย้ายช่องเมื่อพบเรดาร์** (client อาจหลุดชั่วคราว) — ใกล้สนามบินควรระวัง

### 6 GHz (Wi-Fi 6E/7)
- ✅ คลื่นใหม่ **ว่างที่สุด** ช่องกว้างจำนวนมาก (หลายช่อง 160 MHz), ไม่มีอุปกรณ์รุ่นเก่ามาถ่วง, บังคับ **WPA3**
- ❌ ระยะสั้นที่สุด, ต้องใช้อุปกรณ์ที่รองรับ, กฎการใช้งานต่างกันตามประเทศ (ตรวจประกาศ กสทช. สำหรับประเทศไทย)

### Channel Width — กว้างขึ้นเร็วขึ้น แต่…
| Width | ความเร็ว | จำนวนช่องที่ไม่ทับกัน (5 GHz) | ใช้เมื่อ |
|---|---|---|---|
| 20 MHz | ต่ำสุด | มากที่สุด | **พื้นที่หนาแน่น (high-density)**, 2.4 GHz |
| 40 MHz | 2× | ครึ่งหนึ่ง | สำนักงานทั่วไป (5 GHz) |
| 80 MHz | 4× | น้อย | บ้าน/พื้นที่ AP น้อย |
| 160/320 MHz | สูงมาก | น้อยมาก | บ้าน, 6 GHz |
> 🔑 ช่องยิ่งกว้าง ยิ่งเหลือช่องน้อย → AP ข้างเคียงต้องใช้ช่องซ้ำกัน → **co-channel interference** → ช้าลง ในองค์กรจึงมักใช้ 20/40 MHz

## 4. ตัวชี้วัดสัญญาณ (ต้องอ่านเป็น)

### RSSI (Received Signal Strength) — หน่วย **dBm** (ค่าติดลบ ยิ่งใกล้ 0 ยิ่งแรง)
| RSSI | คุณภาพ | เหมาะกับ |
|---|---|---|
| −30 ถึง −50 dBm | ดีเยี่ยม | — |
| **−50 ถึง −67 dBm** | ดี | **VoIP/วิดีโอคอล (เป้าหมาย ≥ −67 dBm)** |
| −67 ถึง −70 dBm | พอใช้ | เว็บ/อีเมล |
| −70 ถึง −80 dBm | อ่อน | ช้า หลุดบ่อย |
| < −80 dBm | แย่มาก | แทบใช้ไม่ได้ |

> 💡 dBm เป็นสเกล log: **ทุก −3 dB = กำลังลดครึ่งหนึ่ง** · −10 dB = ลดเหลือ 1/10

### Noise floor
ระดับสัญญาณรบกวนพื้นหลัง (เช่น −95 dBm)

### SNR (Signal-to-Noise Ratio) = RSSI − Noise
```
 RSSI −65 dBm, noise −95 dBm → SNR = 30 dB ✅
 เป้าหมาย: ≥ 25 dB สำหรับ voice/video · < 15 dB ใช้งานลำบาก
```
SNR สำคัญกว่า RSSI อย่างเดียว — สัญญาณแรงแต่ noise สูงก็ใช้ไม่ได้

### Data Rate / MCS
อุปกรณ์ปรับ **อัตราเร็ว (MCS — Modulation and Coding Scheme)** อัตโนมัติตามคุณภาพสัญญาณ สัญญาณดีใช้ modulation สูง (1024/4096-QAM) สัญญาณอ่อนลดเหลือ modulation ต่ำ (ช้าแต่ทนกว่า)

## 6. องค์ประกอบและการเชื่อมต่อ

### ศัพท์
- **SSID** — ชื่อเครือข่ายที่ผู้ใช้เห็น
- **BSSID** — MAC address ของแต่ละ radio/SSID บน AP (แต่ละ AP มี BSSID ต่างกันแม้ใช้ SSID เดียวกัน)
- **BSS** — AP หนึ่งตัวกับ client ที่เชื่อมอยู่ · **ESS** — หลาย AP ที่ใช้ SSID เดียวกัน (ให้ผู้ใช้ roam ได้)
- **Station (STA)** — อุปกรณ์ client

### ขั้นตอนการเชื่อมต่อ
```
 ① Discovery: AP ส่ง Beacon ประกาศ SSID เป็นระยะ (~100 ms) / client ส่ง Probe Request ถามหาเครือข่าย
 ② Authentication (802.11 open system — ขั้นพื้นฐาน)
 ③ Association: client ขอเข้าร่วม AP ได้ Association ID
 ④ Security: 4-way handshake (WPA2/WPA3-Personal) หรือ 802.1X/EAP (Enterprise) → ได้กุญแจเข้ารหัส
 ⑤ DHCP → ได้ IP → ใช้งาน
```
ถ้าปัญหาอยู่ขั้นใด อาการจะต่างกัน: เชื่อมไม่ได้ (②–④ รหัสผ่าน/RADIUS) vs เชื่อมได้แต่ไม่มีเน็ต (⑤ DHCP/VLAN/DNS)

## 7. ทำไม Wi-Fi ได้ช้ากว่าที่โฆษณา

```
 AP โฆษณา "Wi-Fi 6 AX3000"  → ผลรวม 2.4 GHz + 5 GHz ทุก stream (ทฤษฎี)
 มือถือ 2×2 บน 5 GHz 80 MHz → link rate ~1,200 Mbps (เมื่ออยู่ใกล้มาก)
 throughput จริง (overhead ของ Wi-Fi, half-duplex) ≈ 50–70% ของ link rate → ~600–800 Mbps
 มีผู้ใช้ 20 คนบน AP เดียวกัน/channel เดียวกัน → แบ่งกัน
 อยู่ไกล/ผ่านผนัง → link rate ลดลงมาก
```
- **Airtime** คือทรัพยากรที่แท้จริง: client ที่อยู่ไกล (data rate ต่ำ) ใช้ **เวลาออกอากาศนาน** ทำให้ทุกคนช้าลง → จึงนิยม **ปิด data rate ต่ำ** (1, 2, 5.5, 11 Mbps) ในองค์กร
- **Sticky client:** อุปกรณ์ไม่ยอมย้ายไป AP ที่ใกล้กว่า → แก้ด้วย 802.11k/v, ปิด low data rate, ลด TX power ให้พอดี

## 8. Roaming

ผู้ใช้เดินจาก AP หนึ่งไปอีก AP โดยไม่หลุด — **client เป็นผู้ตัดสินใจย้าย** (ไม่ใช่ AP)

| มาตรฐาน | ช่วยอะไร |
|---|---|
| **802.11k** | AP ส่ง **รายชื่อ AP ข้างเคียง** ให้ client — ไม่ต้องสแกนทุกช่อง |
| **802.11v** | AP **แนะนำ** client ให้ย้าย (BSS transition management) |
| **802.11r (Fast BSS Transition)** | ย้ายแล้ว **ไม่ต้องยืนยันตัวตนใหม่เต็มรูปแบบ** — สำคัญกับ VoIP/802.1X (roam < 50 ms) |

**การออกแบบให้ roam ดี:** สัญญาณทับซ้อนระหว่าง AP ประมาณ 15–20% ที่ −67 dBm, SSID/security เดียวกัน, VLAN เดียวกันหรือมี controller/tunnel รองรับ

## 9. แก้ปัญหา Wi-Fi พื้นฐาน

| อาการ | ตรวจ |
|---|---|
| สัญญาณอ่อน/หลุดบ่อย | RSSI/SNR ตรงจุดนั้น, ระยะห่าง AP, สิ่งกีดขวาง, AP ล่ม |
| ต่อได้แต่ช้า | channel ทับกัน (co-channel), ผู้ใช้หนาแน่น, ใช้ 2.4 GHz, data rate ต่ำ, bandwidth ของ uplink/อินเทอร์เน็ต |
| ต่อไม่ได้ | รหัสผ่าน/802.1X/cert, MAC filter, client ไม่รองรับ security (WPA3) |
| ต่อได้แต่ไม่มี IP | DHCP/VLAN ของ SSID, AP uplink trunk |
| เสียงโทรขาดเมื่อเดิน | roaming ช้า (ไม่มี 802.11r), coverage ไม่ทับซ้อนพอ |
| หลุดเป็นช่วงในช่อง DFS | พบเรดาร์ AP ย้ายช่อง |

**เครื่องมือ:** `netsh wlan show interfaces` (Windows), `nmcli dev wifi` / `iw dev wlan0 link` (Linux), `wdutil info` (macOS), แอป WiFi Analyzer, NetSpot/Ekahau/Hamina (survey), หน้า dashboard ของ controller

## 10. เรื่องที่คนมักเข้าใจผิด

| ❌ | ✅ |
|---|---|
| AP ยิ่งแรง (TX power สูง) ยิ่งดี | ทำให้รบกวน AP ข้างเคียงและ client ติดกับ AP ไกล — ควรปรับให้พอดีกับ client |
| channel กว้างยิ่งดี | ในองค์กรทำให้ช่องไม่พอ เกิด co-channel interference |
| ความเร็วบนกล่องคือความเร็วที่ได้ | เป็นผลรวมทางทฤษฎี จริงได้น้อยกว่ามาก |
| AP เป็นผู้ย้าย client | client ตัดสินใจ roam เอง AP ทำได้แค่แนะนำ |
| 2.4 GHz มี 13 ช่องใช้ได้หมด | ช่องไม่ทับกันมีแค่ 1, 6, 11 |

## 11. Cheat Sheet

```
Wi-Fi = สื่อกลางแชร์, half-duplex, CSMA/CA · IEEE 802.11
Wi-Fi 4 (n) · 5 (ac) · 6 (ax: OFDMA, BSS coloring, TWT) · 6E (+6 GHz) · 7 (be: 320 MHz, MLO)
2.4 GHz: ไกล ช่องน้อย 1/6/11 · 5 GHz: ช่องมาก DFS (เรดาร์) · 6 GHz: ว่างสุด ระยะสั้นสุด WPA3
องค์กร: 20/40 MHz · ช่องกว้าง = ช่องน้อย = co-channel interference
RSSI ≥ −67 dBm (voice) · SNR ≥ 25 dB · −3 dB = ครึ่งหนึ่ง
SSID (ชื่อ) · BSSID (MAC ของ radio) · ESS (หลาย AP SSID เดียว)
เชื่อมต่อ: beacon/probe → auth → assoc → 4-way/802.1X → DHCP
Airtime สำคัญ: ปิด low data rate · Roaming: 802.11k (รายชื่อ AP), v (แนะนำ), r (fast transition)
```

7. ทำไมองค์กรไม่ใช้ channel width 160 MHz
8. BSSID ต่างจาก SSID อย่างไร
9. ทำไมการปิด data rate ต่ำช่วยให้ Wi-Fi โดยรวมเร็วขึ้น
10. 802.11r ช่วยอะไร เหมาะกับงานใด

7. Channel กว้างทำให้เหลือช่องน้อย AP ข้างเคียงต้องใช้ช่องซ้ำกัน เกิด co-channel interference
8. SSID = ชื่อเครือข่าย; BSSID = MAC ของ radio/SSID บน AP แต่ละตัว (ระบุ AP ที่เชื่อมอยู่)
9. ลดเวลาออกอากาศที่ client ไกล ๆ ใช้ด้วยอัตราช้า และกระตุ้นให้ client ย้ายไป AP ที่ใกล้กว่า
10. Roaming เร็วโดยไม่ต้องยืนยันตัวตนใหม่เต็มรูปแบบ — เหมาะกับ VoIP/วิดีโอคอลและเครือข่าย 802.1X
</details>
